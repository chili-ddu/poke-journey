# poke-journey

**웹에서 플레이:** https://chili-ddu.github.io/poke-journey/

`main`에 올리면 GitHub Actions가 Godot 4.7로 Web 빌드를 검증하고 Pages를 갱신한다. 시작 화면과 플레이 자료를 나눠 내려받는다. Web 내보내기 후 `tools/web/package_content.py build/web`로 무손실 압축·분리하고 `tools/web/check_content_build.py build/web`로 전체 자료를 검증한다. 첫 플레이에는 맵·음악과 현재 게임에 쓰는 포켓몬 자료를 준비하며, 다른 종족이 저장된 기록은 해당 진화 계열도 추가로 받는다. 받은 자료는 브라우저가 보관할 수 있는 경우 재사용한다. 빌드별 실제 다운로드 용량은 배포된 `download-sizes.json`에서 확인한다. 키보드·게임패드로 조작하며 소리는 화면과 상호작용한 뒤 재생된다. 브라우저의 저장 데이터는 데스크톱 세이브와 별개이며 브라우저/사이트 데이터 삭제 시 사라질 수 있다. 자동 배포 진행은 [Actions](https://github.com/chili-ddu/poke-journey/actions/workflows/pages.yml)에서 확인한다.

포켓몬 한 마리를 직접 조종하는 탑다운 액션 RPG. UI·글꼴·습득표·기술 데이터의 기준은 플래티넘(pret/pokeplatinum)이다. 지도는 **관동 FRLG 진행·배치 + 성도 HGSS 지리**, 건물·지형 표현은 HGSS를 기준으로 한다. 원작의 타입 상성·능력치·공통 피해 공식을 사용한다. 개인 학습용 프로젝트. 용어는 [docs/glossary.md](docs/glossary.md).

개발 프로젝트명은 `poke-journey`(이전 `poke-arena`, 2026-11-11 변경)이며 정식 게임 제목은 별도로 정한다. 기존 세이브 위치는 유지한다. 프로젝트 폴더는 `poke-journey/`를 사용하며, 이전 절대 경로를 쓰는 열린 작업·검증 기록을 위해 `poke-arena/` 호환 링크를 남긴다. GitHub 저장소는 [chili-ddu/poke-journey](https://github.com/chili-ddu/poke-journey)다.

저장소에는 실행에 필요한 코드·장면·게임 자산과 검증 도구를 포함한다. `docs/`의 기획·검증 기록, `build/`의 실행 파일, `third_party/`의 다운로드 원본과 각종 캐시는 로컬에만 보관한다. 아래의 `docs/` 링크와 예전 절대 경로는 로컬 작업 기록용이므로 새로 복제한 저장소에는 해당 문서가 없다. 자산 재생성 도구를 사용하려면 도구가 참조하는 원본을 별도로 준비해야 한다. 자산별 출처와 이용 조건은 `assets/`의 `CREDITS.md`·라이선스 파일을 확인한다.

**모바일·물리 게임패드(2026-11-11):** A는 대화·점프·HM·오브젝트 행동·확인, B는 취소/뒤로, X·Y·LB·RB는 기술 1~4, LT/RT는 가방/상태, 십자키는 도구, START/SELECT는 메뉴/타운맵이다. 기술은 기본적으로 L스틱 이동 방향이며 R스틱을 직접 조작할 때만 별도 조준한다. 모바일은 SELECT/START를 왼쪽, LT/LB를 RT/RB 왼쪽에 둔다. 타운맵은 공중날기 전에도 볼 수 있고, 실제 비행의 해금·방문 조건은 유지한다. 회피·스틱 누르기·화면 설정 보조 페이지는 배정하지 않는다. 실제 패드 버튼·축 입력 경로가 있으며 실물 장치는 미검증이다. 기존 게임 HUD·화면 위치와 PC 배치를 유지한다. [키 대응·화면·검증](docs/touch_controls/active_gamepad/README.md).

**최신 지도 적용(2026-11-10):** 관동 좌표를 보존하고 성도를 서쪽에 붙인 공통 야외 필드에 숲·산맥·해안을 보강했다. 기존 출입구·저장·진행을 유지한다. [통합 필드·실제 전체도·검증](docs/continent_world/README.md). 헤드리스 회귀 149/149, 실제 왕복 1,152타일·12회 문 이동을 확인했다.

## 도로 진행 제한

노랑시티 첫 방문 전은 약 12레벨 도착을 목표로 한 튜토리얼 구간이다. 야생(풀숲·동굴·수상·낚시)과 일반 도로 트레이너는 최대 10레벨이며 체육관은 입장할 수 없다. 방문 후에는 지역별 범위 안에서 플레이어 -3~+2레벨을 기준으로 출현·전투 레벨을 정한다. 기본 경험치는 기존 원작식의 50%, 플레이어가 상대보다 1·2·3레벨 높으면 추가로 75·50·25%, 4레벨 이상 높으면 0이다. 관장전의 경험치 0과 기존 +3~+7 성장 규칙은 유지한다. 필드 기술은 이야기에서 얻으며, 이슬 승리 후 라프라스의 수상 이동 지원과 마티스 승리 후 피카츄의 동굴 조명 지원은 예외다. 기존에 배운 기술·동료는 보존한다. [레벨 구간·경험치·검증](docs/level_progression/README.md).

24번도로 입구는 다리 보수 공사로 막혀 있으며 노랑시티에 처음 도착한 뒤 열린다. 11번도로는 디그다굴 입구 동쪽에서 잠만보가 길을 막는다. **디그다굴↔갈색시티 통로는 항상 열린다.** 잠만보는 노랑시티 방문만으로 깨지 않으며, 서쪽 안내인에게 방법을 듣고 오랭열매 3개를 건네는 깨우기 이야기를 마쳐야 길을 연다. 해당 도로로의 공중날기도 진행 조건을 따른다. [배치·조건·검증](docs/road_gates/README.md).

## 이야기와 퀘스트

1번도로 첫 진입의 신비로운 새 목격이 서브퀘스트 튜토리얼이다. 그 밖의 지역 서브퀘스트는 노랑시티 첫 방문 뒤 시작한다. 시작 인물의 **!** 표시를 보고 말을 걸면 이야기가 진행되며, **Esc → 이야기 수첩**에서 발견한 단서와 다음 목적지를 확인한다. 전투 뒤 화해·상담·알 맡기기까지 마쳐야 완료되고, 열매와 이야기 경험치는 한 번만 받는다.

달맞이산·실프주식회사·로켓단 아지트·홍련의 독립 조사 단서를 조합하면 비주기 결전이 열린다. 교배집에서 열매 선물과 알을 남기는 이야기까지 완료했다면 포획 뒤 Lv10의 2세로 이어진다. 다른 일곱 관장에게 승리한 뒤 아버지를 되찾고 뮤츠에게 도전한다. [현재 기획과 구현 범위](docs/story-direction.md).

## 실행

```bash
git clone https://github.com/chili-ddu/poke-journey.git
cd poke-journey
godot --editor --path .
```

Godot 4.7 에디터로 `project.godot` 을 열고 F5를 눌러도 된다. 죽거나 클리어한 뒤에는 R 키로 다시 시작한다. 화면은 DS 와 같은 px 단위(원본 UI 1px = 뷰포트 1px, 카메라 줌 1)이고 창은 그 정수 배 중 화면에 들어가는 가장 큰 것. 시야 크기는 `-` / `=` 로 네 단계(`scripts/view_scale.gd`, `user://settings.cfg` 에 저장): ×1.0 384×216(16×9칸) / **×1.17 448×252(18.7×10.5칸, 기본)** / ×1.33 512×288(21×12칸) / ×1.5 576×324(24×13.5칸). 창은 **연결된 화면 중 가장 작은 화면에 들어가는 정수 배**로 열린다(사용자 결정 2026-10-28: 어느 모니터에서 켜도 같은 크기; 이 환경에선 448×252 의 3배 1344×756). 창 크기는 손으로 바꿔도 되고, 안의 그림은 정수 배로만 늘어난다. 4배 창이 들어가는 화면에선 UI 가 3/4, 3배 창에선 2/3 이다. 넓힐수록 상자와 글자가 화면에서 차지하는 비율이 줄어 시야가 트인다(사용자 결정). F11 은 전체화면 토글.

## 시작 화면(PC 박스)과 스타팅 세이브

사용자 결정 2026-10-28. 게임을 켜면 **플래티넘 PC 박스** 화면이 뜬다(`scenes/title.tscn`, `scripts/ui/title_screen.gd`). 박스 1 의 첫 줄에 도감 번호 순서대로 **이상해씨 · 파이리 · 꼬북이**가 들어 있고, 하나를 골라 그 포켓몬으로 플레이한다. 그림은 `python3 -I tools/plat_box.py` 가 pret/pokeplatinum 의 `res/prebuilt/graphic/box.narc` 에서 원작 순서대로 굽는다(줄무늬 바탕 + FOREST 벽지 x 88~256 + 왼쪽 미리보기 판, 손 커서, 원작 아이콘).
- **화면 크기:** PC 박스(원본 256×192)는 창 높이에 꽉 차게 늘린다(사용자 결정 2026-10-29). 좌우로 남는 자리는 박스 바탕으로 채우고, 창 비율이 바뀌어도 따라간다. 정수 배로는 꽉 차지 않아 시작 화면만 소수 배율이다(3배 창 1344×756 이면 약 3.94배라 몇몇 픽셀 줄이 한 칸 두껍다). 게임으로 넘어가면 원래 시야 크기·정수 배율로 돌아간다(`ViewScale.use_title` / `use_game`).
- **조작:** ←→(A·D) 또는 마우스로 고르고 Enter·클릭으로 메뉴. 메뉴는 이어하기(기록이 없으면 새로 시작)·리셋·그만두기. 왼쪽 판에 그 칸의 포켓몬(진화했으면 진화한 모습, 이로치면 이로치 그림과 별)·레벨·마지막 장소가 보인다.
- **세이브:** 스타팅마다 하나(`user://save_bulbasaur.cfg`·`save_charmander.cfg`·`save_squirtle.cfg`). 진화해도 같은 칸이다. **리셋**은 그 칸의 파일만 지우고, 실수로 지우지 않게 한 번 더 묻는다(기본 "아니오").
- **예전 세이브:** 칸이 생기기 전의 `user://save.cfg` 는 처음 켤 때 그 포켓몬의 칸(파이리 계열이면 파이리 칸)으로 옮기고, 원본은 `save_legacy_backup.cfg` 로 이름만 바꿔 남긴다.
- **새 게임 시작 이야기:** 사용자 결정 2026-10-29. 볼 안에만 갇혀 있을 수 없는 내 포켓몬이 최강이 되려고 볼을 탈출하고, 오박사가 "어디 가냐"며 쫓아와 **태초마을 오박사 연구소 문 앞에서 게임이 시작**된다. 기록이 없는 칸으로 시작할 때 한 번(쓰러져 돌아올 땐 없음). 대사는 모두 사용자 승인(`Lang` 의 `intro_*`·`oak_*`).
  1. **검은 화면 독백**(내 포켓몬의 속마음, 화면 가운데 흰 글씨 — 글자 정수 2배, 화면 폭을 넘는 쪽만 1배 — Enter·클릭으로 넘김): 종마다 자기소개("나는 꼬리에 불꽃을 단 / 불꽃 포켓몬, 파이리." 등) → "볼 너머로 바깥세상의 소리가 들려온다. …" → "언제까지 여기 가만히 있을 순 없어! / 저 밖으로 나가서 최강이 되고 말겠어!"
  2. 탁자 위 내 볼에 **2배로 다가간 채** 밝아지며 해설 "아침 햇살이 드는 조용한 연구소. / 그런데 탁자 위 몬스터볼 하나가…". 다가간 동안 HUD 는 글상자만.
  3. 볼이 버둥대듯 세 번 흔들린다(볼 밑동 축, 20°·28°·36°, 점점 빠르게). **흔들릴 때마다 카메라가 한 단계씩 더 다가간다**(3·4·5배, 정수 배라 도트가 번지지 않음).
  4. 마지막 흔들림 끝에 그 자리에서 터지듯 열리고(하얀 빛), 내 포켓몬이 하얀 실루엣으로 커지며 튀어나와 Hop 동작으로 뛰어 탁자 앞 바닥에 내려앉는다(꼭대기 0.9칸, 카메라는 빛과 함께 1배로 빠짐). 탁자 왼쪽의 **오박사**(파이어레드 연구소 지도의 자리 (6,3), 도트 `assets/npcs/prof_oak.png`)가 머리 위에 "!"를 띄우며 놀라 돌아본다.
  5. 오박사 "아니!? 볼에서 혼자 나오다니…!" → 내 포켓몬이 오박사를 한 번 보고 출구로 달아나고, 오박사가 다시 "!" 하며 "어, 얘야! 어디 가는 게냐!? / 기다리거라!" 하고 뒤쫓는다. 이 말은 **"!" 뒤에 큰 대화창**으로 나오고 그동안 내 포켓몬은 멈춰 돌아본다, 창을 닫으면 다시 달리고 오박사가 쫓아온다(사용자 결정 2026-10-30: 대사이니 작은 말풍선이 아니라 대화창).
  6. 출구에 닿으면 암전 → 태초마을 연구소 문 앞(문에서 두 칸 아래). 오박사가 문에서 나와 한 칸 걸어와 "헉헉… 이 녀석, 발도 빠르구나…" → "그 눈빛… 바깥세상에서 / 강해지고 싶은 게로구나." → "허허, 말려도 소용없겠군. / 힘들면 언제든 돌아오너라!" 한 뒤 "이거라도 가져가거라. / 배고프면 먹고 힘내거라." 하며 **오랭열매 3개**를 준다(사용자 결정 2026-10-30, 도구 팡파르, Q 칸에 바로). 그러면 내 포켓몬은 정면으로 돌아서고 오박사는 연구소로 돌아간다. 장소 알림판과 함께 정면을 본 채 조작 시작, 그 자리를 저장.
  - 그 뒤로 연구소에 오면 내 볼 자리만 비어 있고, 오박사에게 말을 걸면 "오, ○○로구나! / 바깥세상은 어떠냐?" → "싸우면 싸울수록 강해지는 법이란다. / 얼마나 성장했는지 가끔 보여 다오."
  - 구현: `Game._begin_opening`·`_step_opening`·`_begin_opening_outside`(상태 `opening`, 세계는 멈추고 `World.step_visual`), `StarterBalls`(탁자 위 볼 — 파이어레드 지도 물건 볼 `assets/fx/item_ball.png`, 자리 이상해씨 (8,4)·꼬북이 (9,4)·파이리 (10,4)), `Mon.appear`(볼에서 나오며 커짐)·`Mon.lift`(그림만 띄움), HUD `monologue`·`cinematic`. 사람 머리 위 "!" 는 도트의 머리 끝 바로 위에 뜬다(트레이너도 같음). 시험 도구는 `Game.skip_opening` 으로 건너뛴다.

## 바깥 세계(태초마을~회색시티)와 저장

게임은 **오박사 연구소 안**(`assets/maps/oaks_lab/`)에서 시작한다. 건물 안은 적도 기술도 없고 걷기만 된다. 아래 문 칸에 서면 **암전(0.25초) 뒤 밖으로** 나오고, 밖은 **태초마을·1번도로·상록시티·2번도로·회색시티가 한 장으로 이어진 지도**(`assets/maps/kanto_south/`, 48×220칸)라 로딩 없이 걸어 다닌다(사용자 결정 2026-10-28: 원작처럼 이어진 세계, 문은 암전 전환). 지도는 pret/pokefirered 의 연결(connections) 정보로 `python3 -I tools/frlg_map.py --region kanto_south PalletTown Route1 ViridianCity Route2 PewterCity --start 24,170` 이 한 장으로 굽고(`--start` 는 저장된 자리 없이 바깥으로 나올 때 서는 칸 — 1번도로), 건물은 `frlg_map.py LAYOUT_PALLET_TOWN_PROFESSOR_OAKS_LAB oaks_lab --start 6,10` 식으로 따로 굽는다(`map.json` 의 `areas` 가 구역 경계, `warps` 가 문). 지도 밖과 어느 원작 지도에도 안 속한 빈 칸(1번도로·태초마을 양옆)은 원작처럼 **그 지도의 테두리 무늬(border.bin)** 로 채워 굽는다 — 바깥은 나무, 건물 안은 검정(원작 그대로), 상록숲은 숲 무늬. `bottom.png` 는 사방 `pad`(10칸) 더 크게 구워 화면이 지도보다 넓어도 비지 않는다(사용자 요청 2026-10-28). 집 두 채(주인공 집 1·2층, 라이벌 집)도 들어갈 수 있고, 상록시티의 나머지 건물(체육관·학교·민가)은 아직 "문이 잠겨 있다". **회색시티는 건물 7곳이 모두 열린다**(사용자 요청 2026-10-28): 포켓몬센터·프렌들리숍·회색체육관·박물관 1·2층(계단으로 오르내림, 문 둘)·민가 둘. 원작 실내 지도를 `frlg_map.py PewterCity_<지도> pewter_<이름>` 으로 구웠다. 화면: [docs/pewter-buildings.png](docs/pewter-buildings.png).

**상록숲은 던전이 아니라 도로와 같은 바깥 세계다**(사용자 결정 2026-10-28). 2번도로의 남쪽·북쪽 관문 건물(`forest_gate_south`·`forest_gate_north`, 원작 실내 지도)을 지나 상록숲 지도(54×69칸)로 들어가고, 숲 안에서도 도로와 같은 걸음 확률식으로 원작 FRLG 상록숲 출현표(출현율 14: 캐터피·뿔충이·단데기·딱충이·피카츄, Lv3~6)대로 나온다. 독침붕은 나오지 않는다. 북쪽 관문을 나서면 2번도로 북쪽을 지나 회색시티다. 지도를 다시 구워 원점이 바뀌면 `DungeonDB.LAYOUTS`(판 번호)·`LAYOUT_SHIFT`(옮겨진 칸 수)로 예전 저장의 좌표를 옮긴다(관동 지도 2판: 2번도로·회색시티가 위에 붙어 120칸 내려감). 화면: [docs/route2.png](docs/route2.png), [docs/forest-gate.png](docs/forest-gate.png), [docs/viridian-forest.png](docs/viridian-forest.png), [docs/pewter-city.png](docs/pewter-city.png).

바깥에선 **서 있는 구역의 출현표**대로 야생 포켓몬이 주변 풀숲(화면 안 우선)에서 튀어나온다. 출현은 **원작 파이어레드 걸음 판정을 "0.5초 = 한 걸음"으로 옮긴 확률식**이다(사용자 결정 2026-10-28: 1초 → 0.75초 → 0.5초, `DungeonDB.wild_chance`, 한 걸음 길이는 `DungeonDB.WILD_STEP`): 걸음당 출현율 %(1번도로 21) + 허탕 보정, 마지막 출현 뒤 (8 − 출현율/10)걸음 동안은 5% 만, **살아 있는 야생이 n 마리면 확률을 n+1 로 나눈다**(1번도로: 걸음당 0마리 21%, 1마리 10.5%, 2마리 7%; 처음엔 n+1 제곱이었으나 직접 해 보니 너무 드물어 바꿈). 걷든 서 있든 굴리고(실시간이라), 동시 마리 수 상한은 없다. 1번도로에서 한 마리를 10초에 쓰러뜨린다고 치면 분당 약 8.3마리, 두 마리 이상과 겹친 시간 약 41%, 셋 이상 약 4%다(20초면 셋 이상이 약 38%). 매 프레임 같은 확률을 나눠 굴려 걸음 단위로 툭툭 나오지 않는다. 태초마을·상록시티는 출현표가 없어 조용하고(회색시티도), **쫓아오던 야생도 마을로 들어서면 도망친다**("야생 포켓몬은 도망쳤다!", 경험치 없음, 사용자 결정 2026-10-28). **풀숲을 지나면 원작처럼 풀이 흔들린다**(사용자 요청 2026-10-28, FRLG 필드 효과 `FLDEFF_TALL_GRASS` 그대로): 발이 풀숲 칸에 들어서는 순간 그 칸에 풀 그림이 생겨 프레임 1→2→3→4 를 1/6초씩(잎이 튐) 보이고, 그 뒤 아래쪽 풀잎(프레임 0)이 발을 덮은 채 남았다가 칸을 벗어나면 사라진다. 플레이어와 야생 모두 같고, 점프 중엔 내려앉은 칸에서 낸다. 원작은 풀 한 칸이 주인공 키의 절반이라 프레임 1(풀 전체)이 아랫도리만 가리는데, 여기선 칸(24px)이 파이리 키와 비슷해 통째로 가려지므로 프레임 1 만 아래 10줄을 그린다. 칸 판정·앞뒤 정렬은 위치 값이 아니라 발(그림자) 기준이다(`Mon.feet_offset`). 화면: [docs/tall-grass.png](docs/tall-grass.png). 멀어진 적은 사라진다. 화면 위 이름표는 서 있는 구역 이름(PALLET TOWN / ROUTE 1 / VIRIDIAN CITY / ROUTE 2 / PEWTER CITY).

비행(F)은 없앴다(사용자 결정 2026-10-28). 문을 지날 때 성장(레벨·경험치·기술·진화·클리어·개체 정보)을 저장하고, **도착한 장소와 자리**를 새 장면이 저장한다(`user://save.cfg`). 다음에 켜면 그 자리에서 이어진다(사용자 결정 2026-10-28: 예전엔 떠나는 장소의 문 칸을 적어서, 껐다 켜면 이미 나온 건물의 출구 매트 위에서 시작했다).

**문이 열리는 기준:** 문 칸(`map.json` 의 `warps`, 위치 값이 있는 칸으로 판정)에 서면 열린다. 갈 곳이 없는 건물(`DungeonDB.WARP_MAPS` 에 없음 — 상록시티의 집·학교·체육관 등)은 **문 칸 자체가 막혀 있어** 올라설 수 없다(사용자 결정 2026-10-30, `Game._lock_doors`; 상록시티 체육관만 비주기 이벤트가 끝난 뒤 막힌다). 왼쪽 위에 뜨던 알림(토스트: 문 잠김·도구 사용·시야 크기 등)은 그리지 않는다(사용자 결정 2026-10-30). 건물에서 바깥 세계로 나오면 문 칸이 아니라 **문 앞 한 칸**(건물 반대쪽, 보통 아래)에 서서 바로 옆으로 걸을 수 있다(사용자 결정 2026-10-29, `Game._door_out_dir`). 건물 안으로 들어가면 지금처럼 출구 매트 위에 서는데, 바로 되돌아가지 않게 문이 아닌 칸을 한 번 밟은 뒤에야 다시 열린다. 단 **문 칸 위에서 막힌 쪽으로 방향키를 누르면 바로 열린다** — 원작 출구 매트(화살표 워프)처럼(사용자 결정 2026-10-28). 그 방향은 '그쪽은 막혔고 반대쪽은 걸을 수 있는' 쪽만이라, 건물 안 매트는 아래(벽)를 누르면 나가고 바깥 문 칸은 위(건물)를 누르면 들어가며, 바깥 문 칸 양옆의 건물 벽 쪽으로는 열리지 않는다(`Game._pushing_wall_on_warp`). 던전을 클리어하면 저장되고 결과 화면에서 R 로 날아온 자리로 돌아온다. 쓰러지면 R 로 **오박사 연구소**에서 HP 가득 찬 채 다시 시작한다(성장은 유지, 사용자 결정: 유지 + 저장). 봇·도구(BOT=1)는 저장을 읽지도 쓰지도 않고 늘 Lv5 파이리로 시험용 풀밭 아레나(`DungeonDB.DEFAULT` = `test_meadow`)에 바로 들어간다(`DUNGEON=` 환경변수로 장소 지정: `oaks_lab`, `kanto_south`, `viridian_forest`, `forest_gate_south` …). **언덕**(원작 MB_JUMP_* 칸, `map.json` 의 `ledge`)은 걸어서는 못 지난다. 내려가는 방향으로 걸으면 원작처럼 저절로 뛰어내리고, **올라갈 땐 점프(Space)로 넘는다(회피는 언덕을 못 넘는다)**(사용자 결정 2026-10-28; 점프는 원작처럼 두 칸(48px)을 Hop 동작(0.4초) 내내 날아가고, 언덕을 넘으면 시작 칸에서 정확히 두 칸 앞, 곧 언덕 바로 다음 칸 가운데에 내려앉는다. 내려앉을 칸이 막혔거나 언덕이면(대각선 포함, 언덕에서 두 칸 떨어져 뛰는 경우도) 점프하지 않는다(사용자 결정 2026-10-28)). 적은 언덕을 못 넘는다. 바깥 세계 흐름(연구소 → 문 → 마을 → 1번도로 출현 → 언덕 내려가기·올라가기 → 2번도로 → 남쪽 관문 → 상록숲 → 북쪽 관문 → 회색시티)은 `godot --headless --path . -s tools/overworld_smoke.gd` 로 확인한다. 화면: [docs/overworld-lab.png](docs/overworld-lab.png), [docs/overworld-route1.png](docs/overworld-route1.png).

- **장소 이름 알림판(사용자 요청 2026-10-30):** 플래티넘 MapNamePopUp 그대로 — 장소 종류마다 원작 그림(마을 town·시티 city·도로 route·숲 forest·건물 안 indoors, 동굴·호수·공원·물가 그림도 받아 둠, `tools/plat_popup.py` → `assets/ui/plat/popup_*.png`)이 왼쪽 위에서 4px/프레임으로 내려와 60프레임 머문 뒤 올라간다. 글자는 원작 자리(y 16)에 검정 + 회색 그림자. 장면에 들어설 때와, 바깥 세계에서 구역이 바뀔 때(1번도로 → 상록시티 등) 뜬다. 경기장과 경기장에서 돌아올 때는 띄우지 않는다. **위쪽에 늘 떠 있던 장소 이름표는 없앴다**(던전만 남은 적 진행 막대로 남음). 화면: [docs/place-popup-town.png](docs/place-popup-town.png), [docs/place-popup-route.png](docs/place-popup-route.png), [docs/place-popup-indoors.png](docs/place-popup-indoors.png).

야외에서 **점프 착지 전에 Space를 한 번 더 누르면** 피죤에게 납치되어 구구들의 둥지로 들어간다. 구구 12마리와 마지막 피죤을 상대하는 이벤트 배틀은 경험치를 주지 않는다. 승리하면 피죤이 원래 자리로 데려다주고 최강을 꿈꾸는 주인공의 “1호 팬”이 되어 날기를 돕는다. 이후 점프 중 Space를 다시 누르면 관동 타운맵에서 현재 구현된 마을·시티 5곳과 도로 8곳을 선택할 수 있다. 방향키·클릭으로 고르고 Space·Enter로 확정하면 친구가 나타나 목적지로 태워 주고 안전하게 착지한다. Esc로 취소하면 원래 점프를 이어간다. 몸집이 커지면 운반 모습은 피죤투가 된다. [이벤트·날기 상세와 실제 화면](docs/bird_friend/README.md).

**달맞이산 사건으로 돌아온 이슬에게 승리하면 이슬의 라프라스가 수상 이동을 돕는다.** 호환 종족은 파도타기를 배우며, 비호환 종족은 물가에서 Space로 라프라스를 부른다. 이전 이슬 승리 기록도 지원한다. 마티스에게 승리하면 피카츄가 돌산터널의 길을 밝혀 주며, 호환 종족은 플래시를 배워 직접 사용한다. 이전 마티스 승리 기록도 지원한다. 별도 라프라스 탈출·피카츄 구출 사건은 제거한 상태다. 이미 획득한 친구와 배운 기술은 보존한다. [현재 이야기와 이동 지원](docs/story-direction.md).

**수련을 마치고 돌아온 웅:** 꼬마돌·투구·롱스톤·프테라의 네 마리를 순서대로 내보낸다. 프테라가 마지막 에이스이며, 도전 레벨에 따라 +3·+4·+5·+7로 성장한다. 투구는 40부터 투구푸스로 등장하고, 관장전 경험치는 0이다. [대사·자산·검증](docs/brock_training/README.md).

**관장 파티 구성:** 웅을 포함한 일곱 관장은 서로 다른 진화 계열 네 마리, 비주기는 다섯 마리를 사용한다. 마지막이 대표 에이스이며 레벨·진화 상태는 도전 시 플레이어 레벨에 맞춘다. 에레브·마그마 계열은 저레벨에서 에레키드·마그비로 출전한다. 이슬·마티스의 필드 지원 보상과 관장전 경험치 0은 유지한다. [전체 구성·진화 기준·검증](docs/gym_rosters/README.md).

라프라스 탑승은 8방향마다 등껍질 위 좌석을 잡고 **몸통 → 주인공 → 앞쪽 목·등껍질 테두리** 순서로 겹친다. 아래와 아래 대각선 방향에서도 등껍질은 주인공 뒤에 두고, 앞쪽 목과 머리만 주인공을 가린다. 아래 대각선의 좌석은 등 중앙 쪽으로 맞춘다. 원본 수영 프레임의 몸통 표식에 좌석을 붙여 함께 움직이며, 주인공은 이동 중에도 걷지 않고 등에 머문다. HD-2D와 2D가 같은 좌석과 원본 도트 마스크를 사용한다. [8방향 탑승 모습](docs/lapras_riding/eight_directions.gif) · [32개 자세 검증](docs/lapras_riding/checks.json). 화면 검증은 `python3 tools/run_visual_test.py tools/lapras_ride_review.gd`, 비교 그림 생성은 `python3 tools/lapras_ride_preview.py`로 실행한다.

**쌍둥이섬 바위 퍼즐:** 바위 앞에서 바라보고 Space를 누르면 한 칸씩 민다. 원작 바위 6개와 구멍 8곳을 사용하며, 떨어진 바위는 원작의 아래층 위치에 나타난다. 위층 두 바위를 지하 3층까지 보내면 그 층의 물살이 멎고, 지하 3층의 별도 네 바위 퍼즐로 두 바위를 더 떨어뜨리면 지하 4층 물살이 멎는다. 물살 정지 후에는 원작의 정지된 맵으로 바뀌어 북쪽 섬까지 파도타기로 갈 수 있다. 해결 전에는 거센 물살에 떠밀려 아래층이나 안전한 육지로 돌아온다. 낙하 도착 지점은 거꾸로 올라가는 계단으로 작동하지 않는다. 위치·낙하·물살 정지는 저장되며, 잘못 밀었을 때는 Esc 메뉴의 **이 층의 바위 배치 되돌리기**로 현재 층에서 움직이는 바위만 복구한다. 이미 아래층에 내려간 바위와 해결한 물살은 유지한다. 현재 밀기는 HM 없이 주인공이 직접 수행하며, 괴력 동료의 획득·지원 연출과 프리져 조우는 별도다. [31번의 실제 밀기 해법](docs/seafoam_puzzle/solutions.json) · [실제 장면 왕복·저장 복구 검증](docs/seafoam_puzzle/checks.json) · [물살 정지 후 북쪽 섬](docs/seafoam_puzzle/11_northern_island_accessible.png). 자산 생성은 `PYTHONPATH=tools python3 tools/seafoam_puzzle_assets.py`, 해법 탐색은 `python3 tools/seafoam_puzzle_solutions.py`, 화면 검증은 `python3 tools/run_visual_test.py tools/seafoam_puzzle_review.gd`로 실행한다.

원작 도감의 **키·몸길이 기준 8단계 크기**를 등록된 493종 전체에 적용한다. 원본 도트가 설치된 63종은 걷기 실루엣을 기준으로 화면 배율을 맞추며, 진화·이로치·야생·동료도 같은 규칙을 사용한다. 큰 포켓몬의 접지 반경은 한 칸 통로를 통과하도록 제한하고 날기 운반 간격·스라크 눈빛도 도트 크기에 맞춘다. [분류 기준과 실제 크기 비교](docs/pokemon_sizes/README.md).

공중날기 호환 종족은 친구 이벤트에서 기술을 배운 뒤 같은 타운맵에서 목적지를 고르고 직접 오른쪽 위로 날아간다. 피죤·피죤투가 태워 주는 경우에는 착륙 중 몸통·얼굴을 고정하고 날개만 움직인다. [자력 비행과 운반 동작](docs/self_flight/README.md).

**필드 기술 직접 사용(2026-11-09):** 풀베기·파도타기·플래시·공중날기는 해당 친구 이벤트를 마치면 호환 주인공이 기술을 습득해 직접 행동한다. 배울 수 없는 종족은 친구의 도움을 받는다. 필드 사용은 전투 기술 칸 장착·PP 소모 없이 가능하며, 기존 친구 저장과 진화 후 습득도 지원한다. [종별 판정·조작·검증](docs/direct_field_hms/README.md).

**달맞이산 삐삐 이동:** 서쪽 동굴 입구에서 삐삐가 R이 적힌 옷을 입은 사람들을 경고하고, 손가락흔들기로 플레이어를 4번도로 동쪽 출구에 보내 준다. 동굴 출구의 로사·로이 전투를 거치지 않으며, 도착 후 동쪽 입구로 돌아가려 하면 막혀 있다는 안내가 나온다. 이동 상태는 저장되고 서쪽에서 재방문하면 다시 도움받을 수 있다. [대사·연출·검증](docs/moon_passage/README.md).

**22번도로 스라크 구출(2026-11-09):** 자신의 강함을 시험하려고 챔피언로드로 향하던 스라크가 망키 무리에게 당했다. 관문으로 향하는 길가에서 발견하면 주인공이 대신 무리와 싸운다. 망키 Lv4 12마리를 3초 간격으로 상대하고 마지막 우두머리 망키 Lv8을 물리치면 같은 자리로 돌아와 친구가 된다. 풀베기 호환 주인공은 기술을 배우고 직접 사용하며, 비호환 종족은 스라크의 도움을 받는다. 예전 상록숲 이벤트는 이전했고 완료·승리 저장을 보존한다. [이야기·위치·화면·검증](docs/route22_scyther_rescue/README.md).

## 트레이너 배틀 (상록숲·회색체육관)


사용자 결정 2026-10-29. 체육관 배틀도 일반 트레이너 배틀 위에 만들고, 체육관일 때만 부가 요소(배지·체육관 트레이너 정리)가 붙는다. 트레이너는 파이어레드 그대로다(`scripts/data/trainer_db.gd`). 지도가 칸토라 파티(종족·레벨·기술, 개체값 0)·대사·자리·시야를 pret/pokefirered 의 `trainer_parties.h`·`text.inc`·지도 `object_events` 에서 옮겼고, 한국어 대사는 파이어레드 한국어판이 없어 옮긴 말이다. 자리는 `DungeonDB` 장소의 `"trainers"`.

- **컷신 → 경기장**(사용자 결정 2026-10-29): 대사가 끝나면 **플래티넘 인카운트 연출**(`scripts/ui/encounter_fx.gd`, 원작 `src/overlay005/encounter_effect_core.c` 를 60fps 프레임 단위로 옮김)이 나오고 **경기장**으로 옮겨 싸운다. 연출은 원작처럼 상대 첫 포켓몬의 레벨로 갈린다 — 내 포켓몬보다 낮으면 검게 두 번 깜빡인 뒤 큰 몬스터볼이 돌며 커지고, 화면이 위·아래 반쪽으로 갈라져 볼 반쪽과 함께 좌우로 밀려난다(Trainer_Grass_LowerLevel). 같거나 높으면 하얗게 깜빡인 뒤 작은 볼 둘이 위·아래 줄에서 엇갈려 구르고 화면이 모서리부터 검게 먹힌다(_HigherLevel). 몬스터볼 그림은 원작 `enc_trainer_high/low.png`(`tools/plat_encounter.py`). **관장은 플래티넘 관장 컷인**(`EncounterEffect_GymLeader` 구조 그대로, 사용자 결정 2026-10-29): 하얗게 한 번 깜빡임 → 관장 띠가 톱니 가장자리로 오른쪽에서 쓸려 들어와 계속 흐름 → VS 가 테두리 잔상 셋과 함께 찍힘 → 검은 실루엣 얼굴이 오른쪽에서 미끄러져 옴 → 화면이 번쩍이며 얼굴에 색이 돌아오고 바탕이 어두워지고 이름이 뜸 → 잠시 뒤 하얗게 사라지고 경기장이 하얀 화면에서 밝아진다. 플래티넘엔 웅 그림이 없어 얼굴은 **파이어레드 웅 트레이너 그림의 상반신을 정수 2배**(플래티넘 얼굴 그림과 같은 96×64), 띠는 같은 바위 타입 관장인 **강석의 띠**를 쓴다(VS 는 원작 그대로). 화면: [docs/encounter-leader.png](docs/encounter-leader.png).

- **들고 다니는 상태:** 경기장 왕복은 HP·PP·성장·가방을 그대로 들고 간다(`Game.carry`). 문으로 장면을 넘을 땐 지금처럼 HP 가 차지만, 배틀에 들어가고 나올 땐 이어진다. 경기장에 들어가기 직전 원래 자리를 저장하므로, 경기장 안에서 끄거나 Esc 로 끝내도 배틀이 걸린 자리에서 이어진다(트레이너는 그대로).
- **이기면:** 원작 순서대로 "○○{과/와}의 승부에서 이겼다!" → 트레이너의 진 대사 → 암전하고 **배틀이 걸린 자리로 돌아온다**. 경험치는 야생과 같은 기본 50%·레벨 차이 보정 규칙을 사용하며, 관장전은 0이다. 트레이너 포켓몬은 도구를 안 떨어뜨린다(원작 파티에 도구 없음). 이긴 트레이너는 저장되어(`[progress] trainers`) 다시 덤비지 않는다. 상금은 돈이 없는 게임이라 없다.
- **볼 던지기(사용자 요청 2026-10-30):** 트레이너가 포켓몬을 내보낼 때마다 아래 큰 대화창에 "곤충채집소년 새미는 뿔충이를 내보냈다!"가 뜨고, 카메라가 트레이너 쪽으로 2배 다가가 손에서 날아가는 몬스터볼을 따라간다. 볼이 내보낼 자리에 닿으면 원작 볼 열림 빛(플래티넘 `pokeballs/open_poke_ball.spa` — 노란 빛 덩이가 확 퍼지고 빛줄기 여섯과 주황 불티가 튐, `World.ball_open_fx`; 예전의 흰 원은 원작이 아니었다, 사용자 지적 2026-10-30)과 함께 흰 실루엣으로 커져 나온다(시작 연출과 같은 `Mon.appear`). 시작 연출의 볼도 같은 빛. 다 나온 뒤에야 대사를 넘길 수 있고(▼ 도 그때 뜬다), 넘기면 0.3초 동안 내 포켓몬 쪽(경기장은 나와 상대 사이) 1배로 돌아와 배틀이 이어진다. 연출 동안 세계는 멈춘다(`Game._send_next`·`_step_sendout`, 볼 그림 `ThrownBall`).
- **배틀 사이엔 플레이가 멈춘다(사용자 결정 2026-10-30):** 상대가 쓰러진 순간부터 쓰러지는 동작·"쓰러졌다!"·다음 포켓몬이 볼에서 나올 때까지(그리고 마지막 상대 뒤 승리 대사 전까지) 내 포켓몬은 움직이지도 기술을 쓰지도 못하고 세계는 그림만 움직인다(`Game._battle_paused`, `World.step_visual`).
- **쓰러뜨림 메시지:** 상대 포켓몬이 쓰러지는 동작(1초)이 끝나면 플래티넘 원문대로 "상대 뿔충이는 쓰러졌다!" / "The foe's WEEDLE fainted!"(사용자 선택). 그 뒤에 레벨업 창, 다음 포켓몬(0.6초 뒤) 또는 승리 대사가 원작 순서대로 나온다.

- **지면:** 지금 쓰러졌을 때와 같다 — 결과 화면에서 R → 마지막 포켓몬센터(HP 가득). 트레이너는 그대로라 다시 도전한다.

- **기술 끼우기(사용자 요청 2026-10-30):** 기술 쪽에서 줄을 한 번 누르면 고르고(상세 판), 고른 줄을 한 번 더 누르면(또는 Enter) — 끼우지 않은 기술이면 **"○○을 어느 칸에 끼울까?" 모달**(L / R / 그만둔다, 지금 끼운 기술 이름을 함께 보여 줌; L·R 키로도 고름, Esc·바깥 클릭으로 닫음), 끼운 칸(L·R)이면 **L ↔ R 맞바꾸기**. PP 가 가득한 칸만 바꿀 수 있다(원래 규칙). 예전의 '집어서 다른 줄에 놓기'는 없앴다. 화면: [docs/summary-tabs.png](docs/summary-tabs.png), [docs/summary-modal.png](docs/summary-modal.png).

가방·상태창은 HUD 보다 크게 그린다: UI 층 배율(m/k)을 되돌려 원본 1px = 게임 화면 1px(창의 정수 배)이라 또렷하다(사용자 요청 2026-10-28). 창을 닫은 직후에는 마우스 버튼을 다 뗄 때까지 기술이 나가지 않는다.
플래티넘 포켓몬 상세창의 위 화면을 그대로 옮겼다(사용자 결정 2026-10-28: 가방처럼 원작 그대로, 천천히 고친다). 쪽은 정보(초록)·능력치(파랑)·기술(빨강) 셋과 닫기 탭이다. 배경·탭·볼·정면 그림은 `tools/plat_summary.py` 가 pret/pokeplatinum 에서 구운 `assets/ui/plat/sum_*.png`·`front/` 이고, 글자 자리는 원작 `window.c` 의 창 배치, 탭·타입 아이콘·정면 그림 자리는 `sprites.c`·`3d_anim.c` 좌표 그대로다.
- **공통:** 쪽 제목, 볼과 이름·레벨, 플래티넘 정면 그림, 지닌 물건(지금은 없음).
- **정보:** 도감 번호, 이름, 타입 아이콘, 어버이(---)·ID No.(트레이너 ID 5자리), 현재 경험치, 다음 레벨까지, 경험치 막대. 이로치면 정면 그림이 이로치 팔레트(`shiny.pal`)로 바뀌고 그림 오른쪽 위 (98,72)에 빨간 별(`sum_shiny.png`)이 붙는다.
- **능력치:** HP 값과 막대, 공격·방어·특수공격·특수방어·스피드, 특성(플래티넘 데이터의 첫 특성, 이름·설명은 PokeAPI — 게임 규칙엔 아직 안 쓴다).
- **기술(바꿔 끼우기):** 위 네 줄은 끼운 칸(Q·W·E·R), 아래 한 줄은 끼우지 않은 배운 기술(넘치면 스크롤). 고른 줄을 한 번 더 누르면 "어느 칸에 끼울까?" 모달(Q·W·E·R·그만둔다, 모달에서 Q~R 키로 바로) — 끼우지 않은 기술은 그 칸에 끼우고, 끼운 기술끼리는 맞바꾼다. 원작의 기술 순서 바꾸기처럼 Enter 로 한 줄을 집고 다른 줄에서 Enter 를 누르면 맞바꾸고, 칸과 배운 기술이면 그 칸에 끼운다. **PP 가 가득인 기술만 칸에서 빼거나 옮길 수 있다**(아니면 제목 자리에 "PP 가 가득 차야 바꿀 수 있다!"). 고른 줄은 빨간 커서와 왼쪽 상세 판(분류·위력·명중률·설명; 한국어 설명은 PokeAPI 의 한국어가 있는 가장 이른 판).

## 진화 화면

사용자 요청 2026-10-30. 진화는 필드가 아니라 **플래티넘 진화 장면을 그대로 옮긴 전용 화면**(`scripts/ui/evolution_screen.gd`)에서 한다. 원작 `src/evolution.c` 의 상태 순서·프레임 수를 60fps 한 프레임씩 옮겼다(`EvolutionScreen._frame`). 그동안 세계는 멈춘다(state `evolve`).
- **흐름:** 필드가 검게 → 화면이 밝아지며 "어…? 파이리의 상태가…!" → SEQ_SHINKA → 두 모습이 하얗게 바래며 위·아래 검은 띠가 40px 까지 들어옴 → **흰 실루엣 교대**: 옛 모습이 줄고 새 모습이 커지기를 번갈아, 한 바퀴마다 두 배씩 빨라짐(배율 256 에서 한 프레임 8 → 16 → 32 → 64) + 빛줄기·노란 빛·네 갈래 별 → 원작 이미터가 다 끝나면(약 200프레임) 색 구슬이 터지며 배경까지 하얗게, 새 모습만 남음 → 띠가 걷히고 반짝임과 함께 색이 돌아옴 → "축하합니다! 파이리는 리자드로 진화했다!" + SEQ_FANFA5(끝날 때까지) → 검게 → 필드로.
- **취소(B·Esc):** 원작처럼 **교대하는 동안만** 받는다. 하얗게 번쩍인 뒤 옛 모습으로 돌아오고 띠·빛·SEQ_SHINKA 가 멈춘 뒤 "어라…? 파이리의 변화가 멈췄다!"(원작 "Huh? … stopped evolving!", 사용자 승인 2026-10-30). 원작처럼 **다음 레벨업 때 다시 진화하려 한다** — 멈춘 종족·레벨은 실행 동안 기억한다(`Game.evolve_declined`, 저장 안 함).
- **필드로 돌아오면** 진화 전 곡을 다시 틀고, 진화한 종족이 그 레벨에 배우는 기술은 필드에서 이어서 배운다(기술 대기열 그대로). 변함없는돌을 지니면 화면이 열리지 않는다.
- **그림:** 배경은 원작이 쓰는 알 부화 배경(`res/graphics/egg_hatch/background.png` + `.NSCR`), 모습은 상태창과 같은 플래티넘 정면 그림, 빛은 원작 파티클 `shinka_demo_particle.narc` 의 텍스처 다섯 장 — `python3 -I tools/plat_evolution.py` 가 pret/pokeplatinum 에서 받아 `assets/ui/plat/evo_bg.png`·`assets/fx/evo_*.png` 로 굽는다(`--spa` 는 이미터 값만 찍음). 이미터 13개의 시작 시각·수명·개수·색·크기 변화는 SPA 값 그대로지만 움직임은 2D 근사이고, 알갱이 크기는 캡처를 보며 맞췄다(원작 3D 카메라 환산을 옮기지 못함). 빛은 실루엣 뒤에 그린다.
- 상태창을 열면 그 포켓몬의 울음소리가 난다(2026-10-30).
- 확인: `test/test_evolution.gd`, `godot --headless --path . -s tools/evolution_smoke.gd`(취소 → 같은 레벨 유지 → Lv17 진화 → 리자드 용의분노), 캡처 `godot --path . -s tools/evolution_shot.gd -- <디렉터리>`. 화면: [대사](docs/evolution-1-what.png) · [교대](docs/evolution-2-alternate.png) · [번쩍임](docs/evolution-3-flash.png) · [진화](docs/evolution-4-done.png) · [취소](docs/evolution-cancel.png).

## 개체값·이로치 (원작 그대로)

사용자 결정 2026-10-28: 보스를 없애고, 개체값과 이로치를 원작과 같게 했다(`scripts/data/individual.gd`).
- **개체값:** 능력치마다 0~31. 원작 4세대 난수기(LCRNG `seed × 0x41C64E6D + 0x6073`)의 "Method 1" 순서대로 성격값(PID) 32비트 → 개체값 묶음 둘(HP·공격·방어 / 스피드·특공·특방, 각 5비트)을 뽑는다. 능력치는 원작 공식 ⌊(2·종족값 + 개체값)·L/100⌋ + 5(HP 는 + L + 10)이고, 노력치·성격은 이 게임에 없다. 야생은 나올 때마다, 내 포켓몬은 새 게임 때 한 번 뽑아 저장한다(`[mon] pid·ivs`). 예전 저장이면 처음 켤 때 뽑아 바로 저장한다.
- **이로치:** 트레이너 ID·비밀 ID(새 게임 때 정해 `[trainer]` 에 저장)와 PID 로 (TID ^ SID ^ PID 위 16비트 ^ PID 아래 16비트) < 8 이면 이로치 — 확률 1/8192. 야생도 내 트레이너 ID 로 판정한다(원작처럼). 성격을 먼저 정하는 플래티넘 야생의 Method J 대신 Method 1 을 쓰는 건 이 게임에 성격이 없어서다(분포는 같다).
- **그림:** 필드 도트는 PMD Sprite Collab 의 이로치 시트(`sprite/<번호>/0000/0001` → `assets/sprites/<번호>/shiny/`, `python3 -I tools/pmd_fetch.py --shiny …`). 보통 시트와 같은 동작만 두고, 구구의 이로치에 없는 넘어짐 두 장은 다른 시트 8장에서 어긋남 0 으로 확인한 공식 이로치 색 대응표로 보통 시트를 칠해 채웠다. 상태창 정면 그림은 플래티넘 `shiny.pal`.
- **반짝임:** 이로치가 나오는 순간(내 포켓몬은 켤 때 처음 한 번) 플래티넘 `res/battle/scripts/common_anims/shiny.s` 를 그대로 옮긴 반짝임이 터진다(`World.shiny_fx`). 파티클 27번(`status_effect.spa`)의 이미터 0·1 수치를 SPL 헤더에서 읽었다: 반짝임 7알이 돌며(프레임당 10°) 퍼지고 흰색→하늘색으로 바뀌며, 뒤이어 둘레에 잔별 8알이 번쩍인다(약 1.2초, 텍스처 10번을 네 갈래로 거울 → `assets/fx/g4_shiny.png`). 원작은 서 있는 전투라 반짝임 중심이 고정이지만, 여기선 움직이므로 몸을 따라간다. 연출 난수는 전투 난수와 따로 쓴다.
- 캡처·시험: `SHINY=1` 이면 새로 뽑는 개체가 모두 이로치. 화면: [docs/shiny-wild.png](docs/shiny-wild.png).

## 배경 음악

사용자 결정 2026-10-29: **장소 곡은 파이어레드, 시스템·배틀·팡파르는 플래티넘**. 모두 원작 데이터(pret 디컴파일의 악보·악기·샘플)를 도구로 직접 합성한 WAV 다(원작과 똑같지는 않은 흉내, `assets/audio/CREDITS.md`). 배치는 `scripts/bgm.gd`(`Bgm`) 한 곳: 장면을 다시 불러도 끊기지 않게 루트에 노드를 하나 두고, 같은 곡이면 문을 지나도 그대로 이어진다.

- **장소 곡**(파이어레드 지도의 music 값): 태초마을·집 = 태초마을, 연구소 = 오박사 연구소, 1·2번도로 = 1번도로, 상록·회색시티와 관문·박물관·민가 = 회색시티, 센터·숍 = 포켓몬센터, 상록숲 = 상록숲, 체육관 = 체육관. 관동 남부 지도는 서 있는 구역(`areas`)의 곡으로 바뀌고, 바뀔 땐 앞 곡을 0.5초 줄였다가 바꾼다. 야생 포켓몬과 싸울 땐 장소 곡 그대로(사용자 결정).
- **트레이너**: 눈이 마주치면(또는 말을 걸면) 플래티넘 눈 마주침 곡(곤충채집소년·캠프보이 SEQ_EYE_BOY) → 인카운트 연출과 함께 배틀 곡(SEQ_BA_TRAIN, 관장은 SEQ_BA_GYM — 플래티넘 관장은 눈 마주침 곡이 없어 컷인과 함께 바로 배틀 곡), 경기장에서도 이어짐 → 이기면 승리 곡(SEQ_WINTRAIN / SEQ_WINTGYM) → 돌아오면 장소 곡. 지면 곡이 멈춘다.
- **팡파르**(원작처럼 잠깐 끊고 울림 — 사용자 결정): 레벨업(SEQ_FANFA1, "자랐다!" 글과 함께), 진화 완료(SEQ_FANFA5), 센터 회복(SEQ_ASA), 도구 받기(SEQ_FANFA4 — 비주기의 변함없는돌). 그동안 배경 곡은 멈췄다가 끝나면 멈춘 자리부터 다시. 팡파르 도중에 곡이 바뀌면 새 곡은 팡파르가 끝난 뒤 시작한다. 진화 화면이 열리면 장소 곡을 멈추고 "…의 상태가…!" 뒤에 SEQ_SHINKA(취소하면 멈춤), 필드로 돌아오면 진화 전 곡을 다시.
- **시작 화면**: SEQ_TITLE01.
- 굽기: `python3 -I tools/frlg_music.py`(파이어레드 7곡, 약 50초) · `python3 -I tools/plat_music.py`(플래티넘 11곡, 약 1분 40초, `sound_data.sdat` 은 없으면 pret 에서 받음). 처음 → 반복 두 번을 굽고 둘째 반복을 WAV smpl 루프로 적어 Godot 가 그 구간을 반복한다. 헤드리스(시험 도구)에선 곡을 고르기만 하고 틀지 않는다. 확인: `test/test_bgm.gd`, `tools/trainer_smoke.gd`(곡 전환).

- **물대포의 물줄기는 쏠 때마다 다르다**(사용자 요청 2026-10-30): 한 묶음마다 무늬(위→아래 훑기 / 아래→위 / 바깥에서 가운데로 / 제멋대로)와 퍼짐 폭(0.8~1.8배)을 뽑고, 방울마다 각도·속도(±12%)·크기(0.8~1.25배)를 조금씩 흔든다(`move_shapes` 의 `vary`, `World._step_bursts`). 맞는 건 여전히 묶음당 한 번.

## 규칙 요약
- **기술의 세 단계(사용자 정의 2026-10-30):** **선딜레이** = 동작 준비(`cast_delay`·`hit_delay`), **동작** = 스킬 동작(공격 도트 한 번, 그동안은 느리게 걷는다), **후딜레이** = 스킬 동작이 끝난 뒤 **다음 다른 스킬을 쓰기까지의 딜레이**(`MoveDB.RECOVER`: 근접 0.55초, 투사체 0.45, 연발 0.55, 던지기·장판·실·변화기 0.6, 자기 강화 0.45, 돌진은 돌진이 끝난 뒤 0.5, 모으는 기술은 쏜 뒤; `Player.skill_lock_t`). 후딜레이는 **연타를 막는 값**이라 어느 칸도 못 쓰지만 움직임은 막지 않고 자세도 붙잡지 않는다. 다만 **근접기(몸통박치기·할퀴기 등 `arc`)는 동작이 끝날 때까지 제자리**에 선다 — 때리는 순간 잠깐 멈추는 맛(사용자 지적 2026-10-30). **근접기는 도트의 달려드는 동작 그대로 앞으로 나가며 치고 돌아오지 않는다**(사용자 결정 2026-10-30): Attack·Strike 도트를 몸이 가장 앞으로 나간 프레임(PMD Offsets 시트의 몸 중심)까지만 재생해 거기서 멈추고(도트의 반), 동작이 끝나면 그만큼 자리를 옮긴다(`MonSprite.lunge_mid`·`lunge_offset`, `Mon.tick_status`). 그동안 **그림자와 카메라도 몸을 따라 앞으로**(`Mon._lunge_shift`·`cam_anchor`) 나가 있어 자리가 옮겨질 때 화면이 한 번에 튀지 않는다(사용자 요청 2026-10-30: 몸통박치기 때 화면 이동이 자연스럽게). 적도 같다. 불꽃엄니만 그 위에 `step` 0.5칸이 더 있다. 구멍파기만 솟구친 뒤 0.8초 서 있기도 한다. 한 칸의 재사용 간격(`USE_DELAY`)과 PP 는 그대로. **물리 근접기의 기본형 = 몸통박치기**(사용자 결정 2026-11-02: '이 몸통박치기의 줌과 공격방식은 모든 물리공격의 기본형'): 모양을 따로 안 적은 물리기와 베어가르기·메탈클로·마구찌르기 등도 달려들며(lunge) 맞는 순간까지 미끄러지고(glide — Strike 13px, 그 밖 6px) 그 자리에 남는다(`MoveDB._melee_default`; 360° 기술·step 기술·`"lunge": false` 는 뺌). 전엔 몸 중심을 발밑에 고정한 채 동작만 재생해 '치고 제자리로 돌아오는' 것처럼 보였다. 3D 카메라도 앞으로 나간 몸(`cam_anchor`)을 초당 비율로 따라간다 — position 을 따라가 동작이 끝나는 순간 목표가 튀어 파이리가 멈춘 뒤에도 화면이 혼자 미끄러졌다(`tools/cam_trace.gd`·`tackle_shots.gd`·`lunge_trace.gd`). **공격 상쇄**: 상대 투사체끼리 닿거나 서로를 향한 물리 근접기(`arc`)의 타점이 0.012초 안에 겹치면 두 기술의 남은 위력을 비교한다. 유리한 타입의 위력에 상성 배수를 적용해 차이를 구한 뒤, 이긴 기술의 배수로 다시 나눈 값이 남는다. 연발 전체가 한 기술로 계산되며 실제 피해는 남은 위력으로 피격 대상의 상성을 적용한다. 무승부 근접기는 양쪽이 반 칸씩 물러난다. 승패가 나면 진 쪽에만 잔여 위력 비율만큼 넉백 거리를 적용한다. 먼저 닿아 상쇄 창을 벗어난 근접기는 상대 준비 동작을 끊는다. **넉백은 힘·몸무게 비율**(사용자 결정 2026-10-30, 공식 3-②): 물리기에 맞으면 미끄러지는 거리 = 기본 3칸(나도 같다) × 2x/(1+x), x = (내 공격 ÷ 상대 방어) × √(내 몸무게 ÷ 상대 몸무게)(랭크 반영, 몸무게는 플래티넘 도감 kg → `species.json` `weight`). 2x/(1+x) 는 힘이 같으면 1, 아무리 차이 나도 2 를 넘지 않는 포화 곡선이라 최대값을 두지 않아도 구구가 화면 밖으로 날아가지 않는다(파이리 Lv12 기준 구구 5칸·딱충이 3.2칸·꼬마돌 1.8칸·롱스톤 0.4칸; 진화해 무거워지면 더 밀고 덜 밀린다). **특수기는 밀지 않고 경직**: 그 자리에서 Hurt 자세로 굳어 움직이지도 기술을 쓰지도 못한다. 경직 = 0.4초 × 2y/(1+y), y = 내 특공 ÷ 상대 특방(상한 0.8초, 내가 맞으면 절반). **원거리 물리기**(투사체·연발·부채꼴 탄·빔·던지기)는 계산된 넉백 거리의 **50%**(사용자 결정 2026-11-09). 초기 속도에 √0.5를 곱해 감속 후 이동 거리를 절반으로 맞춘다. 적과 플레이어 모두 같고, 피해·근접 물리·특수기의 경직은 그대로다. 기술이 넉백을 따로 정한 것(연속찌르기 30)은 유지하며, 원거리 물리기에 개별 넉백이 있으면 같은 거리 보정을 적용한다. **히트스톱**(사용자 결정 2026-11-02): 맞는 순간 맞은 쪽이 잠깐 멈춘다(동작·이동·넉백·경직 모두, 섬광만 흐름) — 근접 물리기(arc·burrow·dash)는 때린 쪽도 같이 **0.14초**, 투사체·특수기는 맞은 쪽만 0.07초, 연타기(연속찌르기) 한 타 0.03초, 쓰러뜨리는 타 0.2초, 급소 ×1.5. 내가 맞을 때도 같다(나와 때린 적만). 나머지 세계와 이펙트는 그대로이고 후딜레이·쿨타임도 흐른다(`Mon.hitstop_t`, `World._hitstop`). **밀려나는 동안·경직 중엔 이동 입력을 받지 않는다**(나·적 모두 걷기 없이 미끄러진다; 회피·점프·언덕 자동 뛰어내리기도 없음 — 키를 누른 채 밀리면 순간이동처럼 튀던 것, 사용자 지적 2026-10-30; 기술은 쓸 수 있다). **쓰러질 때**는 물리기면 다 밀려난 뒤 그 자리에서 넘어지고, 특수기면 경직 자세로 0.3초 버틴 뒤 넘어진다(`Mon.dying_t`; "쓰러졌다!" 글도 그만큼 뒤에). `World.knock_factor`·`knock_speed`·`stun_time`, `test/test_knockback.gd`.
- **돌진 기술은 부딪치면 멈춘다(사용자 결정 2026-10-30):** 객기·돌진·이판사판태클·로케트박치기처럼 몸으로 달려드는 기술은 상대 포켓몬에 닿는 순간 거기서 멈추고(뚫고 지나가지 않음) 그 뒤 후딜레이가 시작된다. 회피·점프는 기술이 아니라 그대로.

- **열매는 들고 다닌다**(사용자 결정 2026-10-28: 세피리아·디아블로 3·4 식 퀵키). 쓰러진 야생이 떨어뜨린 오랭열매(원작 지닌 물건, 20초 뒤 사라짐)에 닿으면 바로 먹지 않고 가방에 넣는다. 종류별 최대 9,999개, 가득 차면 바닥에 남는다. 기술 열 맨 아래 버튼 오른쪽 칸에 Q·아이콘·개수와 쿨타임 게이지. 회복량은 원작 그대로 HP 10. 개수는 저장된다. 건물 안에서는 못 먹는다. 봇은 HP 절반 아래면 먹는다. 먹기 동작은 PMD Eat 시트(파이리·리자드; 리자몽은 시트가 없어 동작 없음)이고 연출뿐이다 — 멈춰 서서 먹을 때만 보이고 움직이면 바로 풀리며, 느려지거나 기술을 막지 않는다(사용자 결정 2026-10-28).

- **PP 는 줄어 있는 동안 저절로 1씩 회복**한다(사용자 결정 2026-10-28: 다 쓴 뒤 한꺼번에 채우는 재장전 폐지). 간격은 **1분 ÷ 최대 PP**(`MoveDB.REGEN_FULL_TIME` 60초 — 0 에서 가득까지 늘 1분): 할퀴기(35) 1.71초, 불꽃세례(25) 2.4초, 연막(20) 3초, 화염방사(15) 4초, 용의분노(10) 6초마다 1. **회복 도중 기술을 쓰면 쌓이던 시간은 0 으로 돌아간다**(예: PP 5 기술은 12초마다 1 — 두 번 써 3, 20초 뒤 4(8초 쌓임), 그때 쓰면 3 이 되고 5 까지 다시 24초). 사용자 결정 2026-10-28. PP 가 바닥나면 기술 버튼에 다음 1 까지의 게이지가 보인다. 연막·회오리불꽃은 하나가 남아 있는 동안 다시 못 쓴다.
- 기술 이펙트는 원작 전투 애니메이션을 흉내 냈다: 할퀴기는 하얀 발톱 자국 셋, 베어가르기는 큰 초승달, 불꽃세례·화염방사는 불티를 흘리는 불덩이, 용의숨결은 보라·하늘색 숨결, 물대포는 길쭉한 물방울, 독침·미사일바늘은 바늘, 실뿜기는 하얀 실, 전기쇼크·번개는 노란 번개, 연막은 검은 연기. 맞으면 하얀 별 모양 섬광이 튀고(불꽃은 작은 불꽃), 뒤로 밀린다. 몸이 부딪히는 것만으로는 피해가 없고 서로 밀어내기만 한다. 돌진은 잔상을 남긴다. 할퀴기·베어가르기는 PMD 의 Strike 동작(0.4초)으로 앞으로 12px 쯤 뛰어들며 치고(0.13초 뒤 판정), 맞은 쪽 몸 위에만 발톱 자국이 덮인다. 헛손질이면 아무 효과도 없다. 불꽃세례는 Charge 동작으로 0.3초 힘을 모은 뒤 원작 불씨 스프라이트(small_ember, 5프레임) 셋을 4프레임 간격으로 일자로 쏜다. 불씨는 날아갈수록 작은 불씨에서 큰 불꽃으로 자라고, 셋은 한 번의 타격으로 친다(같은 상대는 그중 하나에만 맞음, 위력 40). 쏘는 동안 몸짓은 모으는 자세 한 번뿐이다. 쓰러지면 Trip(넘어짐, 파이리·리자드·피카츄)을 쓰고, 없는 종은 Sleep(누워 잠) 동작으로 대신한다. 도트는 PMD Sprite Collab 사이트의 미리보기처럼 프레임 상자를 한자리에 고정하고 그대로 보여 준다(돌아보기·뛰기·공격의 움직임이 시트대로). 상자의 기준점은 아래를 보는 Walk 첫 프레임의 몸 중심(오프셋 시트 `*-Offsets.png` 의 검은 점)으로 한 번만 정한다(`MonSprite.anchor_of`). 쓰러지면 PMD 의 HitGround(눕는 동작, 파이리·리자드·피카츄에 있음)를 재생하고, 없는 종은 피격 포즈를 옆으로 눕혀 대신한 뒤 흐려진다.
- 이동 속도는 스피드 능력치에 비례한다(44 + 스피드 × 2.2, 최대 130px/s). 파이리 Lv5 68px/s(풀숲 2.8칸/초), Lv16 리자드 110px/s. 적도 같은 식이고 종족 보정은 없다(사용자 결정 2026-10-28: 보정이 필요하면 먼저 물어본다). 스피드 랭크(겁나는얼굴 등)와 둔화만 속도를 바꾼다. 적은 한 번에 한 마리씩 3초 간격, 동시에 세 마리까지. 기술을 쓰는 동안(0.25초)은 이동이 30% 로 줄어 때리면서 달리지 못한다. 신중하게 자리를 잡고 공격하는 게임(사용자 결정).
- Lv.16에 리자드로 진화한다(Lv.36 리자몽 데이터도 있지만 MVP 안에서는 닿지 않는다). 진화는 플래티넘 진화 화면에서 한다(위 '진화 화면', B 로 취소).
- 장소는 `scripts/data/dungeon_db.gd` 에 정의한다(바깥 세계 구역별 출현표, 건물, 던전). **보스는 없다**(사용자 결정 2026-10-28). 던전은 지금 시험용 풀밭 아레나(`test_meadow`: 캐터피·뿔충이 Lv4, 단데기·딱충이 Lv5 중 10마리)뿐이고, 나온 적을 다 쓰러뜨리면 클리어다. 옛 `waves` 형식도 코드에 남아 있다. 회복 수단은 오랭열매·상처약 같은 도구다.
- 등장 포켓몬(상록숲·도로): 캐터피(대기 동작 없이 제자리에서 Attack 동작으로 바로 옆 칸을 치는 몸통박치기, 피해 없이 사거리만큼 늘어나는 실뿜기로 스피드 랭크 −1(사용자 결정 2026-10-29: 따로 느려지게 하지 않고 랭크가 이동 속도를 낮춘다, 배틀이 끝나면 풀림) — 걸리는 순간 원작 능력 하락 연출(몸 안에서 파란 무늬가 아래로 흐름, `scripts/view/stat_overlay.gd`)이 나온다), 뿔충이(독침 사격 — 원작 바늘, 30% 로 독 — 지금은 독이 잠겨 있어 걸리지 않는다), 단데기·딱충이(아주 느리게 다가오며 4초마다 단단해지기 — 원작처럼 방어 1단계씩, 최대 6단계 4배, 금속 번쩍임 뒤 능력 상승 연출. 공격기는 없음), 야생 피카츄(전기쇼크, 번개 한 줄기 6칸), 꼬렛·구구(1·2번도로). 독침붕 데이터(연속찌르기 2~5타·독침)는 남아 있지만 지금 나오는 곳은 없다. 벌레는 불꽃에 2배다.
- 능력치는 원작 공식이고 개체값은 원작처럼 능력치마다 0~31(위 "개체값·이로치").
- 적이 주는 피해는 원작 공식 그대로(1배)다. 대신 모든 공격에 준비 동작이 있다 — 졸개는 웅크렸다가(납작해지고 떨림) 짧게(40px) 뛰어든다. 뛰어든 뒤엔 잠깐 멈춰서 때릴 틈을 준다. → `Enemy.WINDUP`, `Mon.RECOVER_DURATION`, `World.ENEMY_DAMAGE_MULT`

## 지도와 카메라

상록숲은 파이어레드·리프그린의 **실제 상록숲 지도(54×69칸)** 를 그대로 쓴다. `assets/maps/viridian_forest/` 에 아래층(`bottom.png`)·위층(`top.png`, 나무 윗부분; 타일 행 띠로 나눠 포켓몬과 y 정렬 — 나무 뒤의 포켓몬은 가려진다)·칸 격자(`map.json`: 통행 불가·풀숲·시작 좌표)가 있다. 지도 한 칸은 원작 16px 을 **1.5배(24px)** 로 키워 그린다 — PMD 도트가 원작 필드 도트보다 커서 풀숲이 파이리보다 작아 보였기 때문. 카메라는 파이리를 따라가고 줌 1 에 뷰포트 512×288(기본)이라 한 화면에 가로 21칸쯤 보인다(시야 옵션으로 16~24칸). 기술 거리의 '풀숲 한 칸'도 24px 이다. 야생 포켓몬은 화면 안의 풀숲 칸에서 풀을 흔들며 나오고, 나무에 막히면 잠깐 옆으로 돌아 나온다. 포켓몬은 지도 아래층 위에, 나무 윗부분과는 깊이 정렬로 그려진다. 출처와 굽는 방법은 [assets/tiles/CREDITS.md](assets/tiles/CREDITS.md). 지도가 없는 테마(옛 풀밭 아레나)는 색칠 방식으로 그린다.

- **나무 뒤로 걷기:** 나무 윗줄처럼 원작에서 뒤로 숨는 칸에 서면 위층이 포켓몬을 덮는다. 바로 아랫줄(나무 아랫부분)은 바닥층이라 칸 밖으로 내려온 발이 나무 위로 삐져나와 보였다(사용자 지적 2026-10-29). 그래서 숨는 칸 바로 아래의 막힌 칸은 바닥 그림을 그 행 맨 위 정렬로 한 번 더 그려 덮는다(`Arena.cover_cells`, `ArenaTop.CoverStrip`). 이제 원작처럼 머리만 나무 위로 보인다.

## 전투 UI (플래티넘 전투 화면)

HUD 는 플래티넘(4세대) 전투 화면의 원본 그림(`assets/ui/plat/`, `python3 -I tools/plat_ui.py` 로 pret/pokeplatinum 에서 뽑음)으로 그린다. **UI 레이어는 창 배율 k 에 대해 m/k 배(`Game.UI_RATIO` 3/4 → m = round(k·3/4))로 축소해 그린다** — 늘리기 모드가 canvas_items 라 UI 1px = 창 m px 의 정수 배로 남아 번지지 않는다(기본 창 448×252 ×4 에선 3/4, HUD 1px = 창 3px; ×3 창에선 2/3). 그래서 HUD 가 보는 화면은 기본 창에서 뷰포트의 4/3 배(597×336)다. 상자 자체도 여백·폭을 줄였고(사용자 결정 2026-10-27~28: 비율 더 작게), 시야를 가리지 않도록 가장자리에 붙인다.
- **왼쪽 위** 상대 체력 상자(`healthbox_enemy.png`: 이름·Lv·HP 막대). **오른쪽 아래** 내 체력 상자(`healthbox_player.png`: 이름·Lv·HP 막대·HP 숫자("/" 는 그림)·EXP 바)와 그 아래 **대사 글상자**(`msgbox.png` = 기본 대화창 틀 `windows/message_box_00`, 흰 테·갈색 띠, 224×44 로 9분할, 두 줄, 글이 없어도 늘 보임 — 사용자 결정 2026-10-28). 둘 다 **오른쪽 끝에 빈틈없이 붙인다**(사용자 결정 2026-10-28). 이름은 시스템 글꼴이지만 **Lv 와 레벨·HP 숫자는 원작처럼 전용 이미지 글자**다: 숫자는 `res/fonts/font_special_chars.png` 의 0~9 를 체력 상자 팔레트 14번(흰색)·2번(그림자)으로 칠한 `hb_digits.png`(battle_main.c `FontSpecialChars_Init(14, 2, 15)`), Lv 는 체력 상자 부품의 성별 없는 Lv 칸(64·65 / 76·77)을 모은 `hb_lv.png`. 자리는 `healthbox.c` 의 VRAM 전송 위치를 OAM 배치(64×64 두 장)로 상자 좌표에 옮긴 값: Lv (88,16), 레벨 (104,20), 현재 HP (64,40) 3칸 오른쪽 정렬, 최대 HP (96,40).
- **왼쪽 아래 기술 버튼 2×2**(Q W / E R, 88×36, 한국어 88×38 — 2026-11-02 네 칸) + 그 위 **도구 편성 칸 1~4**(아이콘·개수·숫자 키, 오랭열매는 먹은 뒤 쿨타임 게이지) — 타입색 틀(NARC 027 버튼 틀을 타입색으로 물들임) 안의 밝은 판에 기술 이름(가운데), 아래에 타입 아이콘(`types/*.png`; 한국어는 한글 딱지)과 PP n/max(좁으면 숫자만). 판 왼쪽 위에 Q·W·E·R 표시, PP 가 바닥나면 다음 1 까지 게이지, 빈 칸은 회색 틀. 키 안내는 없다.
- **대화창** — 넘기는 대화(간호순·점원·트레이너·오박사·시작 이야기의 해설) 동안은 플래티넘 필드 대화창처럼 **화면 아래 전체 폭, 높이 두 배 창** 하나만 보이고(글자도 정수 2배로 두 줄 — 좁은 화면에서 두 줄에 안 들어가는 쪽만 1배), 기술 버튼·체력 상자·안내 같은 HUD 는 숨는다(사용자 결정 2026-10-29, `Hud.msg_rect`). 전투 중 흘러가는 글(내보냈다·자랐다 등)은 그대로 오른쪽 아래 작은 글상자.
- **레벨업 능력치 창** — 시스템 창(`sys_window.png` = `windows/standard_system.png`) 120×84 가 원작처럼 오른쪽, 글상자 위에 아랫변이 6px 겹치게(내 체력 상자를 잠시 덮음). 먼저 +n, 그 다음 새 값. 기술 잊기 창·결과 창도 같은 창 틀. 새 기술 습득 대사는 능력치 창이 끝난 뒤.

## 언어 옵션 (영어 / 한국어)

**기본은 한국어**(사용자 결정 2026-10-29). 예전에 저장된 언어(기본이 영어이던 때 적힌 값)는 처음 켤 때 한 번 한국어로 옮기고(`Lang.DEFAULT_TAG`), 그 뒤 L 키로 고른 언어는 그대로 기억한다. 모든 문구·트레이너 대사의 글자가 그 언어 글꼴에 있는지 `test/test_font_glyphs.gd` 가 본다(영문 플래티넘 글꼴엔 긴 줄표 "—" 가 없어 깨졌다 → "…"). **L 키**로 영어 ↔ 한국어를 바꾼다(`user://settings.cfg` 에 저장, 도구·테스트는 `LANG_CODE=ko` 환경변수). 문구는 `scripts/lang.gd` 의 표에 두 언어로 적혀 있고, 한국어 조사("{은/는}" 꼴)는 앞 글자의 받침을 보고 고른다(숫자는 읽은 소리 기준: 레벨6으로·레벨31로). 포켓몬·기술·타입·능력치의 한글 이름은 `python3 -I tools/ko_names.py` 가 PokeAPI CSV(`third_party/pokeapi/`, BSD-3)에서 `assets/data/names_ko.json` 으로 만든다 — 전국도감 493종·기술 467개라 새 포켓몬도 바로 한글로 나온다. 한국어 글꼴은 갈무리11(`assets/fonts/Galmuri11.ttf`, OFL, 16px 비트맵) — 플래티넘 한국어판 글꼴은 디컴파일에 없어 가장 닮은 무료 글꼴로. 타입 아이콘은 한국어판 그림이 없어 타입색 딱지에 한글 이름을 쓴다.

## UI 글꼴과 글

글은 전부 영문이다(사용자 결정; 포켓몬·기술·타입 이름은 4세대처럼 대문자). 글꼴은 pret/pokeplatinum 의 `res/fonts/font_message.png`(대사·기술 이름·능력치)와 `font_system.png`(체력 상자의 이름)를 `tools/plat_font.py` 로 Godot BMFont(`assets/fonts/plat_*.fnt` + PNG)로 바꾼 것이다. 글자 폭은 같은 폴더의 `.json`, 글자 코드는 `tools/msgenc/charmap.txt`(셀 번호 = 코드 − 1). 영문 대문자 9px·폭 6px. DS 1px = 뷰포트 1px 이므로 16 그대로 그리고(`UiFont`), 그림자(오른쪽 아래 1px)는 `PixelUi` 가 찍는다. 창은 정수 배율로만 늘어난다(`window/stretch/scale_mode=integer`) — 어중간한 배율이면 도트와 글자가 번지기 때문.

HUD 의 글자 자리는 플래티넘 스프라이트를 DS px 로 실측한 값이고, 화면 크기(시야 옵션)가 바뀌어도 `Hud._layout()` 이 매 프레임 다시 잡는다. 글꼴·그림 원본은 personal use 로만(assets/tiles/CREDITS.md 참고).

## 센터 원본 픽셀 경계 검토

`docs/source_object_audit/center_masks/index.html`에서 18개 사물의 원본/분리 결과, 픽셀 소유 영역, 바닥 점유 제안을 비교한다. `objects.json`에 원본 픽셀 좌표, 부착 대상, 가시 영역 마스크, 제안 점유 칸과 원본 충돌의 차이를 기록했다. 상록/회색 센터의 원본 이미지가 동일함을 파일 단위로 검증했다. `tools/center_object_masks.py`는 검토 자료만 생성하며 런타임·원본·충돌 패치는 수정하지 않는다.

확인: 분리된 18개 객체와 잔여 배경의 재합성은 원본과 픽셀 단위로 동일하다. 투명 마스크는 수동 실루엣과 가장자리 배경색 제거를 사용한 검토본이며, 이 검증은 의미상 완벽한 누끼를 보증하지 않는다. 카운터 아래 가려진 면·물건 뒤 벽지는 복원하지 않았다. 남은 배경은 깨끗한 벽지 에셋이 아니라 구멍이 남은 원본이다. 제안 점유 칸에는 원본에서 열린 칸이 있어, 이동 검증 전 충돌 확정/자동 적용을 하지 않는다. 벽걸이는 바닥 충돌을 추가하지 않고, 카운터 위 사물은 부모의 점유 영역을 공유하도록 제안했다. 원본 15개 지도의 해시가 분석 시작 시점과 동일함도 확인했다.

다음 단계: 이 검토 자료를 바탕으로 실제 발밑 위치와 통로 폭을 측정해 점유 칸을 확정하고, 가려진 카운터 면·벽지 복원 범위를 결정한다. 원본의 구워진 그림자를 제거하는 마스크는 아직 별도 검토가 필요하다.

## 원본 사물 분석 — 렌더링 수정 전 기준

`docs/source_object_audit/index.html`은 원본 `bottom.png`와 `top.png`를 합친 타일 좌표 그림과 분류표다. `catalog.json`은 같은 내용을 기계 판독 가능하게 보관한다. 실내 15개 지도를 모두 직접 확인했고 255개 후보/묶음 영역을 기록했다(중첩된 부모·자식과 묶음이 있으므로 실제 사물 수가 아님). 분류는 벽지 / 벽걸이 / 바닥 사물 / 가구 위 사물 / 구조물 / 바닥 무늬. 좌표는 패딩을 제외한 원본 좌표, 오른쪽·아래로 증가하고 끝 좌표는 제외한다.

완료 범위는 의미 분류와 타일 단위 원본 영역이다. 개별 픽셀 누끼, 묶음 항목 세분화, 실제 바닥 점유 칸, 벽걸이 높이, 원본에 구워진 그림자 마스크는 아직 미확정으로 명시했다. `source_solid_tiles`는 원본 충돌 참고자료일 뿐 실제 사물 점유 영역으로 채택하지 않는다. 원본 SHA-256 및 모든 후보 영역의 지도 범위를 검증했다. 이번 작업에서 런타임·맵·에셋·벽 높이·공간 깊이는 수정하지 않았다.

중요 정정: 이전에 시계로 설명한 주택 중앙 물체는 원본상 TV·받침 형태의 바닥 가전 후보이다. 벽 옆의 수납장/주방 장비와 벽걸이 창문/그림을 구분해야 한다. 계단·난간·기둥은 구조물, 깔개·바닥 문양은 바닥 무늬로 분리한다. 연구소/센터의 기계는 원본에서 부모 가구와 겹치므로 지지 대상별 분리가 필요하다. 다음은 센터의 정확한 픽셀 마스크와 바닥 점유 영역을 확정한 뒤 같은 기준으로 주택 가구를 분리하는 것. 실외 지도·전투 경기장은 이번 분석 범위에서 제외했다.

재생성: `/opt/homebrew/bin/python3 tools/source_object_audit.py` 다음 `tools/source_object_catalog.py`(Pillow 필요). 두 도구는 `docs/source_object_audit`에만 출력한다.

연구소 가구 1차 개선: 후처리 없는 비교(`docs/object_audit/flat/oaks-lab-table.png`)에서도 책장 윗면이 거의 흰색임을 확인했다. `scripts/view/furniture_palette.gd`에서 밝은 무채색을 낮춰 하이라이트 여유를 만들고, 윗판의 동일 색 영역 안쪽에 1픽셀 접합 음영을 넣는다. `View3D._house_mat`에서 연구소 table/wallobj 재질에만 적용하며 원본 PNG·해상도·알파·충돌·다른 장소는 유지한다. 책 등 채색된 앞면 무늬는 보존한다. 표면을 새로 그린 고해상도 에셋이 아니라 기존 도트의 런타임 보정이며 측면 열 반복 구조는 아직 그대로다. 실제 화면에서 책장 윗면의 색과 테두리, 녹색 탁자의 안쪽 음영을 확인했다. 비교 후: `docs/object_audit/refined/oaks-lab-table.png`. 관련 테스트: 원본/알파/채색 보존 및 윗판 음영, 기존 View3D 검사.

View3D 테스트 17개 통과. 캡처 `docs/object_audit/wall_refined/center.png`, `pewter-center.png`, `center-wall.png`(벽 가까운 진단 구도, 실제 이동 경로 검증 아님).

센터 위벽 마무리 및 주택 점검: 충돌이 한 줄뿐인 열도 위벽 그림은 두 줄로 유지하도록 지정된 센터·주택 7개 지도의 생성 기준을 보정했다. 센터 상단 몰딩과 시계 아래 벽이 앞뒤로 꺾이는 문제가 해소됐다. 센터 화분·회복 장치는 배경을 제외한 독립 카드로 분리하고 회복 장치에는 카운터 위 높이를 지정했다(완전한 3D 모델은 아님). 카운터에 중복으로 남던 장치 그림은 인접 바닥 무늬로 대체했다. 원본 지도·워프는 유지하며 생성 에셋과 충돌 패치는 재생성했다. View3D+센터 팔레트 테스트 20개 통과. 실제 화면 확인: 두 센터, 주인공 집 1·2층, 라이벌 집, 회색시티 민가 1·2. 캡처 `docs/object_audit/homes/`.

추가 발견(미수정): 주인공 집 1층 계단 옆 위벽의 전후 위치/높이 단차, 주인공·라이벌·회색시티 민가 수납장 옆의 얇은 카드와 주방 기구의 평면 표현. 다음 단계는 주택 벽 가구를 원본 사물별로 분리하는 것. 이번 검증은 렌더링 및 생성 데이터 검사이며 각 집을 걸어서 출입하는 플레이스루는 하지 않았다.

센터 벽지·벽걸이 분리 및 한 칸 확장(사용자 요청): 상록/회색 센터 위벽 높이를 기존 3칸에서 4칸으로 늘렸다. 화면·지도는 원래 벽 그림에서 제거하고 높이 1.5칸의 별도 카드로 배치한다. 바닥 가구 및 카운터 위 장치와 독립적으로 위치를 조절할 수 있다. 벽지 확장색을 기존 주황색으로 고정해 사물 제거에 따라 최빈색이 바뀌는 현상을 방지했다. 원본 PNG는 유지하며 생성 에셋만 갱신했다. View3D 테스트 19개 통과, 상록센터 일반/근접 구도 확인: `docs/object_audit/wall_layout/center.png`, `center-wall.png`. 다른 집의 추가 한 칸 확장은 아직 적용하지 않았다. 그림자 전체 제거는 이번 작업에 포함하지 않았다.

사용자 정정 — 한 칸 확장은 벽 높이가 아니라 공간 깊이: 직전 센터 벽 3→4칸 높이 변경을 취소하고 다시 3칸으로 생성했다. 벽걸이 분리는 유지한다. 이후 기준은 벽지/벽걸이/바닥 사물 및 카운터 위 사물로 나눠, 위쪽 바닥 공간 한 줄을 확보하는 것. 공간 확장은 아직 미적용이며 지도 좌표·이동 판정·2D/3D 표시를 함께 맞춰야 한다. `wall_layout` 캡처는 정정 전 높이 비교 자료로 현재 상태를 나타내지 않는다.

센터 벽 높이 재정정: 이전부터 존재했던 기본 +1칸도 제거하여 센터의 일반 위벽은 원본 두 칸 높이로 낮췄다. 양끝 사선 벽은 원본 길이를 유지한다. 화면·지도 바닥 기준 높이도 1.5→0.75칸으로 낮춰 벽 안에 맞췄다. 두 센터 생성 완료, View3D 테스트 19개 통과, 상록센터 근접 렌더링 확인 `docs/object_audit/wall_lowered/center-wall.png`. 공간 깊이 확장은 별도 미완료 작업이다.

## 화면 느낌: HD-2D 시제품(2026-11-02)

옥토패스 트래블러 같은 HD-2D 를 해 보기(사용자 요청)의 **1단계 — 2D 그대로 그림 위에만 얹는다**(`scripts/view/look.gd`, `assets/shaders/hd2d_post.gdshader`). 게임 로직·판정은 그대로. 비교 캡처 `docs/look_compare.png`(왼쪽 평면·오른쪽 HD-2D: 1번도로 낮 / 상록숲 / 상록숲 불꽃세례), 도구 `tools/look_shot.gd`.

- **켜고 끄기:** 게임 안에서 **F8**(비교용). 기본값 `Look.DEFAULT_MODE = "hd2d"`, 끄려면 `"flat"` 또는 실행할 때 `LOOK=flat`.
- **후처리**(월드 위·UI 아래 층, UI 는 그대로): 화면 위·아래 띠가 점점 흐려지는 **틸트시프트**(미니어처를 내려다보는 깊이감), 채도·대비 조금 위로 + 그늘은 서늘하게·밝은 곳은 따뜻하게, **비네팅**, 아주 밝은 채색 픽셀만 살짝 번지는 블룸.
- **조명:** 장소마다 화면을 조금 어둡게 깐다(`CanvasModulate` — 낮 바깥은 거의 그대로, **상록숲은 그늘지게**). 그 위로 **파이리 꼬리불**이 발밑을 밝히고, **불꽃·번개 투사체**가 날아가며 둘레를 밝히고(빛무리 포함), 불꽃세례가 맞은 자리가 번쩍인다(`PointLight2D`). 조명은 장소가 어두울수록 세다(`Look.light_gain`). **포켓몬·효과 도트는 조명을 받지 않는다**(`light_mask 2` — 꼬리불이 제 몸을 비추면 하얗게 날아갔다).
- **발광:** 불꽃·번개·섬광 효과 텍스처는 가산 합성으로 그린다(`Look.EMISSIVE`, 어두운 색은 제외). 화면 밝기만 보는 블룸은 낮의 모래길까지 번져서 약하게만 남겼다.
- **2단계(진짜 HD-2D) 시제품 — 3D 로 세운 지도**(2026-11-02, 태초마을부터, `scripts/view/view3d.gd`). 게임 안에서 **F9** 로 2D ↔ 3D(기본 켜짐, 끄려면 `VIEW3D=0`). 판정·이동·기술은 **지금의 2D World 그대로**이고 그 상태를 3D 로 비춰 그린다(포켓몬 도트의 현재 프레임은 2D 그리기가 정한 것을 그대로 쓴다).
  - **카메라**: 높이각 **40°**(처음 55° → 사용자 "각도 더 낮게"), 화각 30°(원근은 은은하게), 2D 와 비슷한 크기. 비교는 실행할 때 `V3D_ELEV=35` 처럼(각도별 캡처 `docs/view3d_angles.png`). 마우스 조준은 바닥과의 교점으로 바꿔 준다(`World.aim_override`).
  - **지도**: 아래층 그림이 바닥 판. **서 있는 칸**(위층이 있거나 막힌 칸 — 나무·집 벽·지붕·울타리·표지판·우체통)을 `tools/hd2d_cards.py` 가 **물체 한 줄씩**(나무 한 그루, 집 한 채의 세로 한 줄) 묶어 그 밑단에 카드 한 장으로 세운다(`hd2d_atlas.png`·`hd2d_cards.json`). 높이는 고정(1칸 = 1m, `STAND`)이라 **낮은 각도일수록 우뚝 서고 뒤를 가린다**. 묶음은 세로 줄에서 '위층이 시작되는 칸'(나무 윗부분)에서 끊고, 같은 숲·건물의 옆 줄 끊는 자리도 합친다(경계 숲 오른쪽 반은 위층이 듬성듬성). 처음엔 칸마다 세우고 높이를 각도에 맞춰 줄였는데, 그러면 각도를 낮춰도 물체가 서 보이지 않았다.
  - **건물·가구는 상자로**(사용자 2026-11-02: 오브젝트에 x·y — 바닥 넓이 — 가 있어야 자연스럽다): 원작 그림은 상자를 비스듬히 내려다본 모습이라, **앞면** = 아래 칸들(벽·창문·문·책상 앞)을 세우고, **윗면** = 위 칸들(지붕·책상 윗면)을 그 깊이만큼 수평으로 덮고, **옆면** = 물체 양 끝에 앞면 가장자리 픽셀 줄을 늘여 붙인다(옆 상자와 붙은 쪽은 안 그림). 40° 카메라에서 앞면 1칸 0.77 · 윗면 1칸 0.64 로 원작 비율과 거의 같다. 대상: 4칸 넘는 묶음(건물·절벽 — 앞면 2칸, 문 줄도 옆 줄과 같은 높이) · 건물 안 2~3칸 가구(앞면 1칸, 뒷벽 y ≤ 1 은 세운 판). 나무·울타리·표지판·꽃·수풀처럼 얇은 것은 세운 판 그대로. 지붕은 평평한 윗면(박공·모임지붕도 해 봤지만 평평한 게 낫다 — 사용자 2026-11-02). 거쳐 온 것: 통째로 세움(지붕이 벽처럼) → 지붕만 38° 눕힘(길게 늘어남) → 시선에 수직으로 눕힘 → 상자. 캡처 `docs/view3d_boxes.png`.

## 기술 연출: 원작 / 커스텀(2026-11-02)

기술 연출은 두 모드가 있다(`scripts/data/fx_style.gd`). **원작** = 지금까지 만든 플래티넘 연출 재현, **커스텀** = 이 게임 컨셉(탑뷰 실시간 액션)에 맞춘 연출 — **어디까지 맞는지(판정 범위·방향)가 보이고 맞는 순간이 또렷하게**. 텍스처는 커스텀도 플래티넘 파티클을 그대로 쓰고, 선·고리처럼 범위를 알리는 표시는 도트처럼 또렷한 선(안티에일리어싱 없음)으로 직접 그린다. 커스텀은 `MoveShapes.CUSTOM_FX` 에 적힌 기술의 그림 키(`fx`·`hit_fx`)만 바꾸므로 **판정·위력·타이밍은 두 모드가 같다**(`test/test_fx_style.gd` 가 지킨다). 비교 캡처 `docs/fx_compare.png`(왼쪽 원작·오른쪽 커스텀), 도구 `tools/fx_compare_shot.gd`.

- **되돌리기:** 전부 원작으로 = `FxStyle.DEFAULT_MODE = "original"`(또는 실행할 때 환경 변수 `FX=original` 로 비교), 한 기술만 = `MoveShapes.CUSTOM_FX` 에서 그 줄 삭제, 게임 안에서 = `FxStyle.set_mode("original")`. 원작 연출 코드는 손대지 않고 그대로 있다.
- **할퀴기·몸통박치기는 공격하며 약 1칸 전진, 박자는 도트에 맞춘다**(사용자 요청·재검토 2026-11-02): 준비 자세(팔을 젖히는 프레임) 동안은 제자리, **팔을 뻗기 시작하는 프레임부터** 몸이 앞으로 미끄러지고(`glide` 할퀴기 13px·몸통박치기 6px, 맞는 순간 0.06초 뒤까지), **맞는 판정은 앞으로 다 나간 프레임**에 — 히트스톱도 그 자세에서 걸린다(`Mon.lunge_timing`·`MonSprite.lunge_start`·`lunge_hit_frame`). 그 자세에서 0.1초만 머물고(`LUNGE_HOLD`) 원래 자세로, 자리는 도트가 나간 만큼 옮겨져 합쳐 약 1칸. 상대 몸에 닿거나 벽이면 미끄러지기는 거기서 멈춘다. 적도 같다. (처음엔 준비 자세에서 미끄러지고, 할퀴는 프레임보다 0.13초에 먼저 맞아 멈췄다가 할퀴고, 0.2초 넘게 굳어 있었다.) 프레임 캡처 `docs/scratch_timing.png`, 도구 `tools/scratch_frames.gd`.
- **할퀴기**(`claw_c`) — 맞으면 작은 발톱 자국 + 짧은 타격 터짐. **범위 호는 그리지 않는다**(사용자 2026-11-02 — 처음엔 판정 끝을 따라 흰 호가 헛손질에도 그어졌다. `Fx swipe` 그리기는 남아 있다).

## 최신 습득표 기술(2026-11-02, A안: 데이터는 최신 판·연출은 플래티넘 파티클)

습득표를 최신 판으로 바꾸면서 데모 구간(Lv5~16)에 들어온 기술. 4세대에 없던 기술(땅고르기·떨어뜨리기)은 위력·타입·PP 를 PokeAPI 값으로 보충하고(`moves.json` 에 `gen` 키, `tools/latest_learnsets.py extra_moves`), 연출은 플래티넘 파티클을 조합했다. 효과음은 각 기술의 플래티넘 `anim.s` 첫 SE(5세대 기술은 돌떨구기·지진 SE 를 빌림). 캡처 `docs/latest_moves.png`, 도구 `tools/latest_shot.gd`.

FRLG 시절 연출 그림은 모두 지웠고 능력 변화 무늬만 3세대 그림이다.

- **새 랭크:** 특수공격(성장) · 특수방어(러스터캐논) · 회피율(달콤한향기). 명중은 원작처럼 "쓰는 쪽 명중 − 맞는 쪽 회피"로 계산한다(지금처럼 적의 공격에만 적용). **랭크 초기화**(사용자 결정 2026-10-29): 원작은 배틀이 끝나야 풀리므로, 주변에 적이 하나도 없으면(풀숲에서 나오는 중인 녀석도 없으면) 내 포켓몬의 랭크 변화를 모두 0 으로 되돌린다(`World.step` → `Mon.reset_stages`). 바깥 세계는 야생 마리마다 따로 배틀인 셈이라 다 쓰러뜨리거나 도망치면 풀리고, 던전은 적이 한 마리씩 나오므로 다음 녀석이 나오기 전 빈 틈에도 풀린다. 적이 없을 때 쓴 성장·껍질에숨기는 곧바로 풀린다(원작도 배틀 밖에선 못 쓴다).
- 시험: `test/test_moves.gd`(27개를 실제 World 에서 써서 피해·상태를 확인, 방어·비·반동·흡수·혼란).

## 데이터: 플래티넘(4세대) 디컴파일에서 생성

포켓몬·기술 데이터는 손으로 적지 않는다. `python3 -I tools/plat_fetch.py` 가 pret/pokeplatinum 에서 필요한 파일(포켓몬·기술·TM JSON, 경험치 표, 글꼴, 전투 UI 그림, 창 틀, 출현표)을 `third_party/pokeplatinum/` 에 받고, `python3 -I tools/gen_gen4.py` 가 `assets/data/{species,moves,exp_tables}.json` 을 만든다(전국 도감 493종, 기술 468개, TM/HM 번호, 원작 순서의 자력기, 원작 경험치 표). 게임은 그 JSON 을 읽고 두 가지 손 표만 덧씌운다:
- `scripts/data/move_shapes.gd` — 기술의 액션 모양(사거리·탄·판정·연출·도트 동작·적 쿨타임). 여기 있는 기술만 "게임에 들어 있는" 기술이다. 없는 기술은 분류별 기본 모양(물리 근접 1칸 / 특수 투사체 4칸 / 변화는 효과 이름으로 랭크 변화 추정).
- `scripts/data/species_extras.gd` — 종의 액션 값(몸 반지름·AI·적일 때 쓰는 기술·속도 배율). 없는 종은 기본값.
플래티넘 효과는 게임 효과로 옮긴다(burn_hit → 화상 확률, flinch → 풀죽음, paralyze → 둔화, high_critical → 급소 1/8, multi_hit → 2~5타, *_damage_flat → 고정 피해). **새 포켓몬 추가 = `assets/sprites/<도감번호>/` 에 PMD 도트 + (원하면) extras 한 줄.** 기술 id 는 pret 폴더 이름(smoke_screen, thunder_shock …).

### 카운터 소품 이동 검토

`tools/review_counter_placement.py`로 원위치·모두 제거·안쪽 이동·위쪽 이동 4개 합성본과 검정/흰색 가장자리 비교를 생성했다. 결과는 `docs/source_object_audit/center_masks/counter_restored/placement/index.html`. 이동 후 원위치의 빈틈·잔상은 육안으로 보이지 않았고, 소품이 덮지 않은 픽셀이 복원 카운터와 동일하며 입력 파일이 변경되지 않음을 검증했다. 화병 하단의 회색 테두리/음영은 남아 함께 이동한다. 이는 2D 합성 검토이며 게임 시점·깊이 정렬·충돌 검증은 아직 하지 않았다. 다음은 센터의 실제 배치에서 소품 접지점·깊이 정렬과 기존 음영의 중복 여부를 확인한다.

### Godot 카운터 접지·깊이 검토

`godot --path . --script tools/counter_3d_review.gd` 실행 후 `python3 tools/counter_3d_report.py`로 검토 보고서를 만든다. `docs/source_object_audit/center_masks/counter_restored/godot_review/index.html`에 실제 Godot 6개 렌더를 기록했다. View3D 카메라/실내 조명 상수를 사용하며 소품 밑단과 윗면 높이 일치를 assert한다. 원위치/이동 × 그림자 유무, 청록 표식 앞뒤 가림을 비교했다. 광원은 그대로 유지하고 geometry shadow casting만 전환한다. 화병 하단 회색 음영은 동적 그림자를 꺼도 남는다. 윗면 0.5칸 높이와 원본 y55 분할은 검토 가정이다. 옆면·뒷면·게임 충돌·팔레트·후처리는 검증 범위 밖이다. 다음은 카운터 옆면/뒷면을 정의한 뒤 센터 지도에서 캐릭터 통행과 가림을 검증한다.

### 두 센터 지도 카운터 검토

`tools/counter_review_model.gd`는 U자 윗면·원본 앞면·추정한 7개 둘레 면과 소품을 검토 모델로 만든다. `godot --path . --script tools/center_counter_walk_review.gd`는 상록/회색 센터를 로드해 기존 카운터 하나만 실행 중 교체한다. 원본·게임 기본 모델·충돌은 수정하지 않는다. 앞 경계 z=4, 높이 0.5칸은 검토 배치다. `python3 tools/center_counter_map_report.py`로 `docs/source_object_audit/center_masks/counter_restored/map_review/index.html`을 생성한다.

두 지도 12장 렌더 및 앞/좌/우 582개 중심선 표본의 Arena.resolve 검사를 완료했다(플레이어 반경 8px, 막힘 0). 내부 직접 배치에서 하체 가림, 사선에서 옆/안쪽 면을 확인했다. 사선 캡처 시 카메라를 옮긴 뒤 캐릭터 카메라 보정도 다시 계산한다. 표본 검사는 NPC 상호작용·실제 입력 이동·내부 출입 가능 여부까지 보증하지 않는다. 숨겨진 면은 앞면 한 열 반복으로 만든 추정 디자인이다. 다음은 검토 모델을 정식 생성 경로로 옮기고 회복 장치 받침 위치와 함께 센터 배치를 통합한다.

### 센터 카운터 정식 적용

상록·회색 센터의 정식 `hd2d_cards.py` 생성 경로와 `View3D`에 U자 카운터를 적용했다. 윗면·앞면·7개 둘레 면을 구성하고 화병 2개·명패를 별도 카드로 생성한다. 검증한 원본 분리 에셋은 `assets/tiles/center_objects/`로 승격하고 좌표·해시·추정 복원 내역을 `provenance.json`에 보관했다. 게임 실행은 docs/tools에 의존하지 않는다. 원본 지도와 충돌 데이터는 그대로다.

회복 장치는 기존 1.1칸 표시 높이를 유지하며 밑단을 0.5칸 높이의 별도 받침에 맞췄다. 카운터와 받침의 숨겨진 면은 원본 앞면 패턴을 사용한 추정 면이다. 화병의 구워진 음영은 유지한다. `COUNTER_PRODUCTION=1 godot --path . -s tools/center_counter_walk_review.gd`로 두 지도 12장과 통로 582개 표본(막힘 0)을 확인했다. 캡처 도구는 CaptureWindow.park를 사용한다. View3D 테스트 20개 통과. 다음은 같은 객체 분리 기준을 일반 주택 TV·책장·벽걸이에 적용해 벽지 잔여 도트와 접지 위치를 정리한다.

### 일반 주택 객체 경계·배치 적용

`tools/home_object_specs.py`에 주택 5곳의 TV 4개·책장 2개·창문 4개·액자/지도 3개·달력 1개의 명시적 원본 경계를 정의했다. `hd2d_cards.py`는 해당 객체를 자동 벽 연결성 추정에서 분리해 정식 생성한다. 배경 제거는 같은 행의 벽지색과 일치하면서 가장자리와 연결된 픽셀만 대상으로 한다. TV/책장은 앞면 전체를 보존하고 깊이 0.4칸, 창문/액자/달력은 벽 앞 z=2.025·밑단 높이 0.9칸의 별도 카드로 배치한다. 액자 왼쪽과 달력 오른쪽/아래쪽 누락 경계를 원본 대조 후 보완했다.

벽 높이·방 크기·원본 지도·충돌 설정은 변경하지 않았다. 주인공 2층 중앙 TV는 기존 모델을 유지했다. 원본 벽지 수평 띠와 사물 음영도 유지한다. `docs/home_objects_integrated/index.html`에 집별 캡처와 좌표를 기록했다. 다음은 주방 싱크·수납장·작은 원통 소품의 자동 분리 경계를 같은 방식으로 명시해 뒤쪽에 남은 얇은 면과 바닥 접점을 정리한다.

### 주택 주방 객체 정식 적용

주인공 1층·라이벌 집·회색시티 민가 두 곳에 싱크, 수도꼭지, 수납장, 원통 소품을 명시적으로 분리했다. 수납장의 정확한 원본 x범위는 33..56(주인공 집은 +16), 원통은 56..64다. 이전 타일 단위 범위는 옆 물건과 빈 배경까지 포함해 본체에서 떨어진 얇은 옆면을 만들었다. 싱크는 y32에서 윗면/하부장을 나누고 수도꼭지 밑단을 0.5칸 윗면에 맞춘다. 가려진 윗면 48픽셀은 같은 행 x16의 온전한 도트로 추정 복원한다. 원통은 실루엣 카드로 유지한다.

사물 제거 뒤 바닥은 지정한 깨끗한 바닥 타일의 같은 위상을 참조한다. 가까운 식탁 깔개를 복사해 색 조각이 남던 문제를 수정했다. 원본 파일·벽 높이·방 크기는 유지한다. `docs/home_kitchen_integrated/index.html`에서 4개 집의 최신 화면과 복원 범위를 확인한다. View3D 테스트 21개 통과. 다음은 계단·난간·계단 앞 깔개 경계를 분리해 층간 이동 지점과 가림을 확인한다.

### 주택 계단·난간·깔개 분리

`tools/home_stair_specs.py`로 주인공 집 1·2층의 계단 구성요소를 분리했다. 깔개와 내려가는 계단 그림은 별도 바닥 레이어, 1층 올라가는 계단은 독립 실루엣, 2층 난간은 앞/측면 카드다. View3D 카드 생성에 decal/side_card 배치를 추가했다. 1층 계단 앞에서 벽 밑선이 튀어나오는 자동 분류도 보정했다. 원본 파일과 층 이동 칸 (10,2)은 유지한다. 계단 단별 입체화는 하지 않았고 난간 높이 0.5칸은 표현상 설정이다.

`godot --headless --path . -s tools/home_stair_smoke.gd`는 별도 세이브 경로로 충돌 보정 접근 및 실제 1층→2층→1층 전환을 검사한다. 양쪽 도착 (10,2), 왕복 통과. View3D 테스트 22개 통과. `docs/home_stairs_integrated/index.html`에서 계단 진입부/난간 앞뒤/측면을 비교한다. 난간 뒤 캡처는 접근 불가능한 칸에 직접 배치한 진단이며, 기존 캐릭터 카메라 보정으로 발이 윗선에 가까워 보이는 한계가 있다. 다음은 의자·화분의 바닥 접점과 통행 범위를 정리한다.

### 주택 의자·화분 접지 및 통행

`tools/home_seat_specs.py`로 주택 4곳의 의자 각 4개(기존 목록의 6개 후보를 정정)를 원본 실루엣으로 분리했다. 깔개 무늬·외부 그림자를 제외하고 1칸 높이 카드로 배치한다. 의자 밑 깔개는 같은 위상의 온전한 패턴으로 복원한다. `collision_patch.json`에 block 항목을 추가하고 Arena가 open 뒤에 적용해 의자 칸을 통과하지 못하게 했다. 원본 map.json은 그대로다.

화분 배치와 기존 잎 아래 통과/화분 한 칸 충돌은 유지하며, 화분 아래 단색 패치를 인접한 같은 줄 마루로 복원했다. 플레이어 반경 8px 기준 의자 칸 차단·잎 아래 통과·식탁 둘레 1,040개 표본의 통행을 검사했다(막힘 0). View3D 테스트 24개 통과. `docs/home_seats_integrated/index.html`에 집별·화분 근접 화면을 기록했다. 의자는 완전한 입체 가구가 아닌 실루엣 카드이며 앉기/NPC 이동은 검사하지 않았다. 다음은 실내 조명·접지 그림자의 밝기와 강도를 방 전체 기준으로 맞춘다.

### 실내 조명·접지 그림자 조정

실내 3D 기본광·후처리 발광 번짐·노란 색조를 낮추고 꼬리불 및 효과 국소 조명 에너지를 35%로 조정했다. 캐릭터/NPC 접지 그림자 알파는 실내 0.24~0.08로 완화하며 높이별 크기와 착지 위치 표시는 유지한다. 2D 및 야외 후처리는 기존 값을 사용한다. 원본 도트 음영과 방 구조는 변경하지 않았다.

주택·센터·연구소 및 야외 전후 캡처는 `docs/indoor_lighting/index.html`에서 비교한다. View3D 테스트 25개 통과. 캡처 종료 시 기존 ObjectDB/resource 해제 경고가 남는다. 다음은 실내 초점·배경 흐림 범위를 점검해 카운터와 뒤쪽 가구의 도트 가독성을 개선한다.

### 실내 초점 범위 조정

실내 3D 틸트시프트의 위쪽 띠를 30%→12%, 아래쪽을 20%→10%, 최대 흐림 반지름을 9px→3px로 줄였다. 중앙 선명 영역은 화면 높이의 78%다. 야외·2D에서는 기존 값을 복원하며 대화 상대 초점 기능도 유지한다. 주택 1·2층, 두 센터, 연구소, 야외의 전후 화면은 `docs/indoor_focus/index.html`에서 비교한다. 캡처별 카메라 보간/애니메이션 시점은 조금 다를 수 있다.

View3D 테스트 25개 및 기존 대화 초점 상태 검증 통과. 캡처 종료 시 기존 ObjectDB/resource 해제 경고는 남는다. 다음은 실제 실내 이동 중 사물과 캐릭터의 가림 순서를 점검해 책장·계단·카운터 옆을 지날 때의 시각적 겹침을 확인한다.

### 실내 이동 중 가림 검토

`tools/indoor_occlusion_review.gd`로 책장 앞·난간 앞/옆·계단 진입부·두 센터 카운터 앞/옆 7개 경로를 World.step 이동 입력 및 충돌 처리로 걸었다. 442 이동 프레임, 모든 중간 목표 도착(허용 오차 0.8px), 35장 캡처를 검토했다. 별도 실제 계단 왕복도 통과했다. `docs/indoor_occlusion/index.html`에 결과를 기록했다. 비정상적인 몸 잘림은 확인되지 않아 게임 렌더링은 변경하지 않았다. 전경 TV 뒤에서 캐릭터가 완전히 가려지는 구간은 위치 가독성 개선 후보다. 점프·다른 체형·전체 지도는 이번 범위에 포함하지 않았다. 다음은 가구 뒤 캐릭터 위치 표시 방식을 검토한다.

### 가려진 실내 플레이어 실루엣

`assets/shaders/occluded_player.gdshader`와 View3D의 플레이어 전용 보조 판으로 실내에서 사물에 가려진 픽셀만 청록색 알파 0.38로 표시한다. 프레임 UV·발 기준·카메라 보정 후 위치/크기를 공유한다. NPC/적 제외, 쓰러짐·땅속 숨기·야외에서 비활성화한다. 깊이를 기록하지 않는 반투명 사물은 가림 기준에 포함되지 않을 수 있다.

`tools/occluded_player_check.gd`로 동일 프레임의 표시 on/off, 전체/부분 가림, 열린 공간 RGB 차이 0 및 상태 전환을 검증했다. 기존 이동 7개 경로와 View3D 테스트 25개 통과. `docs/occluded_player/index.html`에서 비교한다. 현재 Compatibility 렌더러에서 확인했고 다음은 다른 체형과 점프 중 표시 정렬을 검토한다.

### 체형·점프 실루엣 검토

`tools/occlusion_body_review.gd`로 꼬렛·이상해꽃·롱스톤·리자몽의 네 방향 정지, Hop 도트 20/50/80% 시점, 열린 공간 32개 자세를 64장으로 비교했다. 열린 공간 표시 on/off RGB 차이는 네 종 모두 0. 별도 통행 가능한 복도의 실제 점프 100프레임에서 판 정렬을 검사했고 네 종 모두 예정 착지 위치 오차 0px였다. `docs/occlusion_bodies/index.html`에서 확인한다. 정지 가림 위치는 직접 배치한 시각 진단으로, 모든 체형의 해당 지점 통행을 보증하지 않는다.

### 큰 체형 실내 카메라 여유 공간

### 센터 회복·계단·출입문 통합 흐름
